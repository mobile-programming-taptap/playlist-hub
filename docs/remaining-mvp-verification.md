# 남은 조건부 검사 · 2026-11-09

사용자가 기존에 제외된 항목의 검사와 발견된 문제 수정을 요청했다. 실제 계정은 삭제하지 않도록 명시했다. 최신 노션의 프로젝트 홈·명세서·관련 회의록·논의·범위 결정 할 일을 확인했으며, 미확정 후보를 새 요구사항으로 추가하지 않았다.

## 검사 환경

- 기존 앱의 키와 설정을 고치지 않고 `/tmp`에 소스 복사본을 만들어 카카오 키가 없는 앱을 빌드했다. 사용자 데이터가 없는 별도 에뮬레이터에서 실행했다.
- 카카오 응답은 모의 제공자를 사용한다. 테스트 사용자에게 새 인증 증명을 전달하고 탈퇴시키는 앱·서버 처리를 검사하며 실제 카카오 사용자 계정을 삭제하지 않는다.
- PostgreSQL 15.19의 새 컨테이너와 메모리 임시 저장소를 사용한다. 기존 `playona-db` 컨테이너 및 팀 서버 DB는 검사 대상으로 사용하지 않는다. 전체 재검사마다 새 빈 DB를 만든다.
- 실제 OpenAI·MusicBrainz·YouTube API 검사는 별도 메모리 DB와 임시 세션으로 수행한다. 키·인증 토큰을 결과 문서에 저장하지 않는다.

## 확인 결과

카카오 키 없는 빌드의 관련 검사 8개가 통과했다. 기존에 제외된 키 미설정 안내·계정 보존과, 비밀번호 없는 카카오 탈퇴 증명 전달을 포함한다. 게스트 세션 분리·취소·실패·늦은 응답·화면 회전도 함께 검사했다. 조건부 제외는 없다.

PostgreSQL의 기존 이메일 계정 마이그레이션·카카오 사용자 분리·새 기기 세션·목록과 반응 복원·잘못된 탈퇴 증명 거절·정상 증명에 의한 테스트 사용자 삭제·기존 두 세션 무효화 검사가 첫 실행에서 통과했다. 별도 기존 계정은 보존되는 것도 확인했다.

YouTube 계정 연결이 없는 테스트 세션에서 서버 API 키만으로 두 곡의 실제 재생 영상 정보를 찾는 검사가 첫 실행에서 통과했다. 연결된 Google 계정의 토큰을 재사용한 결과가 아니다.

## 발견한 문제와 수정

실제 AI 검사에서 12개 후보 중 6개만 검증됐고, 보충 후보 생성이 약 4초의 제한시간에 걸렸다. 기존 구현은 보충 조회 전 곡 검증에 최악의 재시도 시간 12초를 모두 남겨두어, 남은 전체 시간이 충분해도 AI 요청이 너무 짧아질 수 있었다.

전체 30초 제한은 유지하면서 한 번의 곡 조회에 필요한 6초를 남기고, 실제 곡 검증에도 남은 전체 제한시간을 전달하도록 수정했다. 임의 곡 추가, 검증 조건 완화, 고정 후보 대체는 하지 않았다. 느린 첫 AI 응답 11초·곡 검증 3.5초·보충 생성 4.5초를 재현한 검사에서 검증된 8곡을 30초 안에 반환했다. 보충 실패 시 기존 검증 결과만 유지하고 보충을 한 번만 하는 검사도 유지했다.

첫 전체 검사와 실패 로그는 보존했다. 두 번째 실행은 첫 실행 데이터가 남은 전용 DB를 재사용하여 빈 DB 전제 검사에서 실패했으므로 중단했다. 이는 사용자 DB나 제품 데이터 손상 사례가 아니다. 최종 재검사는 새 빈 DB에서 수행한다.

추가 실제 검사에서는 기존 기본 모델이 잘못된 곡명·아티스트 조합을 생성하는 문제도 확인했다. 더 긴 제한시간만으로 해결되지 않았다. 같은 요청 형식으로 모델을 비교했고 `gpt-5.4-mini`에서 실제 곡 12개 전부를 검증했다. 제이팝은 조건 반영 후 7곡·7.06초, 드림 팝은 8곡·5.76초였다. 원문 표기·곡 검증·요청 조건을 완화하지 않고 기본 모델과 설정 예제·README를 함께 변경했다. `OPENAI_MODEL`로 명시적으로 지정한 모델은 계속 우선한다.

모델의 Responses·구조화 출력 지원과 추론 기본값은 [OpenAI 공식 문서](https://developers.openai.com/api/docs/models/gpt-5.4-mini)에서 확인했다. 호출 단가는 기존 기본 모델보다 높다. 모델 응답은 여전히 비결정적이므로 모든 요청의 곡 수·취향 적합성을 보장하는 결과는 아니다. 검사 도중 MusicBrainz의 실제 503 오류도 확인했으며, 첫 실패 기록은 유지한다.

## 최종 결과

- 서버 72개 모두 통과. 실패·오류·조건부 제외 0개. 실제 AI 검사 2개, 계정 미연결 YouTube 검색, PostgreSQL 카카오 계정 검사까지 활성화했다. 일부 고정 H2 전용 검사는 계속 H2를 사용한다.
- 키 없는 앱의 카카오 검사 8개 모두 통과. 실패·제외 0개.
- 최종 전체 실행에서 실제 제이팝 8곡·6.23초, 드림 팝 8곡·9.81초. 단계별 검사에서 후보 12개 중 10개를 검증하고 8개를 추천했다.
- 빌드한 실제 서버 JAR을 별도 메모리 DB로 실행하여 HTTP 추천 8곡·5.8초를 확인했다. 임시 게스트 삭제 후 이전 세션 거절도 확인했고 검사 서버를 종료했다.
- 같은 JAR의 두 JVM 재시작·기본 파일 DB 보존·응답 유실 후 중복 방지 검사가 통과했다. 최신 JAR을 팀 서버에 반영하고 기존 DB를 유지한 채 정상 실행·포트 소유 프로세스·파일 해시를 확인했다.
- APK/JAR 및 기존 릴리스 AAB의 비밀 값 검사에서 발견 사항 0개. AAB는 과거 산출물을 검사했으며 이번에 재빌드한 릴리스가 아니다.
- 임시 PostgreSQL 컨테이너와 검사 에뮬레이터를 종료·제거했다. 기존 사용자 계정에 대한 삭제 요청은 하지 않았다.

## 근거와 한계

로그·JUnit 결과·키 없는 검사 APK와 최종 파일 식별값은 [검사 자료](../output/checks/remaining-mvp-2026-11-09/)에 보관한다. 최종 검사 수치는 해당 폴더의 `verification.json`을 기준으로 한다. 이전 날짜의 검증 결과는 [MVP 검증 기록](mvp-acceptance.md)에서 구분한다.

실제 카카오 제공자에서 테스트 계정을 새로 가입하고 삭제하는 실인증 작업은 수행하지 않았다. 실기기 검사는 사용자의 실기기가 없어 수행하지 않았다. 외부 API 응답 품질·일시 장애까지 항상 성공한다고 보장하지 않는다.
