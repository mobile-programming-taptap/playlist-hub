# 검사와 근거

조건부로 제외됐던 항목의 추가 검사는 [2026-11-09 검증·수정 기록](remaining-mvp-verification.md)을 따른다.

최신 MVP 재검증은 [2026-11-08 검증 기록](mvp-acceptance.md)을 따른다. 아래의 날짜별 기록은 당시 빌드의 근거이며 현재 결과와 구분한다.

2026-10-19 출시 수준 구현의 최종 로컬 검수 기록이다. 실제 공개 배포·스토어 제출은 사용자 요청 범위에서 제외했다. 파일 식별값과 기기별 결과는 [검증 요약](verification.json)에 보관한다. 모의 플랫폼 응답, 실제 패키지 서버 통신, 실제 외부 서비스 확인을 구분한다.

## 최종 검사

- **서버 H2:** 52개 중 51개 통과, 실패 0개, PostgreSQL 전용 1개 제외.
- **PostgreSQL 설정 서버 실행:** 52개 모두 통과, 실패·제외 0개. 빈 전용 PostgreSQL 15 DB를 사용했다. 독립 H2 전용 fixture는 이 실행에서도 H2를 사용한다.
- **공유 core:** 추천 조건·대화·유지/제외·출처 경계·언어·부정 표현·목록 공유 assertion 검사 통과.
- **Android 17/API37:** 43개 모두 통과. **Android 7/API24:** 42개 모두 통과. 런타임 제외·실패 0개이며, API24에서는 최소 SDK37인 권한 검사 1개가 탐색 단계에서 제외된다. 두 실행은 같은 앱 APK와 검사 APK를 사용한다.
- **Android 빌드:** 디버그 APK·검사 APK·서명 전 릴리스 APK·AAB·lint 통과. lint 오류 0개이며 경고 73개는 남아 있다. 제출용 서명과 실제 스토어 업로드를 수행한 결과는 아니다.
- **실제 패키지 서버:** 파일 DB를 서로 다른 JVM에서 다시 열어 소유권·반응·목록·순서·곡 스냅샷·중복 방지와 첫 생성 응답 유실 후 같은 ID 재시도를 확인했다.
- **Docker·로컬 HTTPS:** 최종 JAR과 컨테이너 JAR의 해시가 일치한다. 호스트 이름과 전용 CA 검증, 읽기 전용 파일시스템·UID10001, 프록시/앱/DB 재시작 보존, 실제 pg_dump를 새 DB에 복원하는 검사 등 15개를 통과했다. 신고·차단·게시 동의 복원과 위조된 전달 주소의 인증 제한 우회 차단도 포함한다. 공개 HTTPS 서비스 검사는 아니다.
- **비밀·개인 파일 검사:** 소스·설정·문서와 APK/JAR/AAB 내부를 읽어 설정된 비밀 값의 원문·URL/base64 표현과 사설 설정/DB 포함 여부를 검사했다. 최종 기록은 `output/checks/release-quality/final-secret-scan.json`이다. 공개 클라이언트 ID는 의도적으로 제외하며 알려지지 않은 비밀까지 없음을 보증하는 검사는 아니다.

장시간 실행에서 드러난 H2 2.4.240의 연결 교체 후 CHECK IN 오류는 [상위 이슈4308](https://github.com/h2database/h2database/issues/4308)와 같은 실패로 재현했다. 수정 버전2.5.252를 명시하고 실제 물리 연결을 퇴출하는 회귀 검사2개를 추가했다. 이전2.4.240에서 만든 합성 DB 파일 복사본의 데이터 보존, 새 쓰기, 유효하지 않은 값 거절도 확인했다. 제약 조건을 없애거나 기존 사용자 DB를 변경하는 방식은 사용하지 않았다. 근거는 `output/checks/release-quality/h2-retirement/`다.

기기 검사는 새로 만든 격리 에뮬레이터 두 대에서 수행했다. 기존 사용자의 에뮬레이터와 저장 데이터는 검사 대상으로 사용하지 않았다. 계정·게시 규칙 동의·공개·두 번째 계정의 신고/차단/해제는 이 최종 JAR을 실행한 키 없는 별도 서버에 앱을 연결해 확인했다. 영상·Google/Spotify·카카오 응답 fixture 검사는 실제 제공자의 실계정 승인과 구분한다.

신고·차단·게시 규칙의 최종 화면과 기존 화면·큰 글씨·입력/목록 팝업을 검사했다. 화면은 전용 검사 계정과 곡 데이터를 사용한다. 이전 진단에서 확인한 검색창 닫기 시점과 화면 밖 신고 사유 선택은 실제 탭/스크롤로 교정했고, 구버전 규칙의 실제 400 응답은 최신 규칙 재확인으로 복구하도록 고쳤다. 같은 오류가 반복돼도 복구 버튼은 한 개만 남도록 제어한다. 이전 APK에서 새 회귀 검사가 중복 버튼으로 실패하는 것을 확인했으며, 증거는 `output/checks/release-quality/android-community-before-modal-sync/recovery-before-fix-proof/`에 보존한다. 실패를 포함한 이전 진단은 `output/checks/release-quality/android-community-before-stale-rules-fix/`와 `android-community-before-recovery-slot-fix/`에 보존한다. 과거 10월13일 검사는 `verification.json`의 `historicalVerification`과 [기능별 기록](full-feature-status.md)에서 해당 빌드의 근거로만 남긴다.

## 외부 서비스 확인과 남은 제약

현재 `backend/.env`에 있는 OpenAI 키는 공식 모델 목록 API에서 **401 `invalid_api_key`**로 거절됐다. H2 수정 전 JAR(`076dcc96…`)에서 시도한 추천 요청도 인증 단계에서 503으로 종료됐다. 이후 최종 JAR의 실제 AI 추천 검사는 사용자 요청으로 제외했으며 성공했다고 기록하지 않는다. 결과를 고정 곡으로 대체하지 않았다. 사용자가 실제 AI 연결 검사를 제외하고 완료하도록 명시했다. 나중에 실제 추천을 사용할 때 새 키를 같은 비공개 설정에 넣고 임의 장르·언어·이어서 요청을 확인한다. 원문 키·인증 토큰·외부 비공개 목록은 검수 문서에 기록하지 않는다.

이번 최종 빌드의 실계정 Google/Spotify/Kakao 승인·실제 목록 전송과 실제 휴대폰은 재검사하지 않았다. 과거의 실제 OpenAI·Google 연결 기록이 현재 빌드의 전체 외부 기능 성공을 대신하지 않는다. 공개 도메인·운영자 문의·제공자 공개 승인·제출 서명은 실제 운영 시에 설정할 항목이며 이번 작업에서 공용 서비스를 만들거나 스토어에 제출하지 않았다.

HTML/Canvas 문서의 데이터 일치·상호작용/타입 검사 결과는 `output/checks/release-quality/documentation-inventory.json`의 실제 실행 범위를 따른다. 실제 Canvas 호스트 미리보기와 브라우저 시각 검사를 대신했다고 기록하지 않는다.

## 2026-10-23 비공개 팀 테스트 · 자동 서버 연결

개발자가 지정한 HTTPS 기본 주소로 최초 동의 후 연결하고, 서버 주소 입력은 디버그의 접힌 개발자 설정으로만 제공한다. 앱 기본 주소가 변경되면 기존 서버 토큰을 복사하지 않고 새 출처를 사용하며, 이용 거절과 기기 목록은 보존한다. 기본 주소 미설정 개발 에뮬레이터만 맥의 로컬 서버를 자동 선택한다.

API24의 선택 회귀 검사 11개가 통과했다. 기본 주소 초기화·명시적 기기 선택 유지, 동의 전 API 요청 0회, 동의 후 메타데이터 조회, 화면 재생성·동일 세션 재사용, 연결 실패 후 주소 입력 없는 재시도, 기존 동적 추천·저장·쓰기 실패·회전 복구를 확인했다. 추천과 플랫폼 응답은 모의 응답이며 실제 AI를 호출하지 않았다. 디버그·Android 검사 APK·미서명 릴리스 빌드가 성공했고 lint는 오류 0·경고 72개다.

맥의 Tailscale Serve HTTPS로 실제 `/health`와 브라우저 소개 페이지 접근에 성공했다. API37 에뮬레이터에서도 실제 Android ApiClient로 동일한 비공개 HTTPS `/health`를 호출한 별도 1개 검사가 통과했다. 이 검사는 명시적 `serviceHealth=true` 인수로만 실행하며, 기본 CI는 비공개 주소에 접근하지 않는다. Serve 상태는 tailnet only이며 Funnel 설정은 없다. 기존 서버 DB와 암호화 키를 보존한 채 기본 URL·플랫폼 콜백 환경 설정을 변경했다. 기기의 기존 출처별 토큰은 새 출처로 자동 이전하지 않는다. 서버의 aiConfigured는 키 설정 여부이며 AI 인증·추천 성공 증거가 아니다.

산출물은 `output/team-testing/TapTap-debug.apk`, 파일 식별·검증 범위는 `output/team-testing/manifest.json`, 실제 검사 결과는 `output/team-testing/android-api24-checks.log`다. `output/release-quality/`의 10월19일 검수 파일은 덮어쓰지 않았다. 새 APK는 기존 별도 에뮬레이터에도 데이터 유지 설치했다.

팀원의 초대 수락·서로 다른 네트워크의 실휴대폰 접속, Google/Spotify 콘솔의 새 콜백 등록·실계정 승인, 실제 AI 연결은 아직 확인하지 않았다. 맥 서버·Tailscale이 꺼지거나 맥이 잠자기 상태이면 원격 사용이 중단된다. 실행 방법은 [비공개 팀 테스트](team-testing.md)를 따른다.


## 2026-10-28 추천 오류 원인 분석 · 실제 앱 검증

이 검증은 0~2곡 추천·고정 장르 안내 오류를 대상으로 한다. 최신 노션은 연결이 없어 확인하지 못했으며 새 제품 요구사항을 추정하지 않았다. 앞선 10월19일 릴리스 검수 파일은 보존했다. 현재 추천 수정이 반영된 실행 파일은 `output/server/taptap-backend.jar`이고, 식별값은 `output/checks/recommendation-reliability/manifest.json`에 기록했다.

확인한 원인은 이전 서버 패키지 실행, AI의 번역·로마자 표기에 따른 실제 녹음 정보 불일치, 정상 MusicBrainz 응답을 1MB 제한으로 거절한 문제, 외부 API의 503·시간 초과였다. 별도 실제 검사에서는 요청한 세부 장르를 이웃 장르로 바꾸는 모델 해석도 확인했다. 발매 원문 표기와 정확한 장르 보존 지침·스키마를 보완하고, 최대 4MB 응답·총 12초 안의 한 번 재시도·검증 탈락 시 한 번의 제한된 추가 AI 제안을 적용했다. 추가 호출도 사용 한도에 포함하며 원래 조건·유지곡·제외곡과 엄격한 곡 정보 검증을 보존한다. 고정 곡 목록이나 검증하지 않은 곡으로 부족분을 채우지 않는다.

별도 빌드 출력 경로에서 서버 63개 검사 중 60개가 통과했고 실패 0개, 실제 API 전용 2개와 PostgreSQL 전용 1개는 기본 검사에서 제외됐다. 동적 카탈로그 9개에는 큰 정상 응답 허용·과대 응답 거절·503 한 번 재시도·느린 첫 응답 후 재시도·보충 실패 시 기존 결과 보존이 포함된다. 실행 로그·JUnit 원본은 `output/checks/recommendation-reliability/`에 보관한다.

실제 API에서는 ‘슈게이즈 음악 추천해줘’가 `genre:shoegaze`를 유지하며 8곡/9.790초, ‘신나는 제이팝’이 8곡/16.786초였다. 같은 검사에서 뒤이어 실행한 드림팝은 MusicBrainz가 재시도까지 503을 반환해 실패했다. 해당 실패 원본도 보관했으며 전체 실제 API 검사가 모두 성공했다고 간주하지 않는다. 외부 API 장애와 AI 분류 품질은 여전히 결과에 영향을 준다.

실행 서버 교체 후 기존 데이터가 있는 API37 설치 앱에서 제이팝 요청을 직접 입력했다. 최초 후보와 한 번의 보충을 합친 24개 제안 중 12개가 실제 곡 검증을 통과했고 앱에는 최대치인 8곡이 표시됐다. 화면은 `app-jpop.png`, UI 계층은 `app-jpop-ui.xml`, 같은 실행의 서버 수치는 `app-server-counts.log`다. 첫 곡은 Catch the Moment / LiSA, 표시 조건은 신나는 · J-pop이다. 이번 검증은 다른 네트워크의 실휴대폰, 전체 OAuth 재연결, 모든 장르의 AI 정확도, 모든 앨범 이미지 가용성을 보증하지 않는다.

503 이후 별도 실제 드림팝 요청에서는 원래 `dreampop` 조건을 유지하고 24개 제안·10개 곡 검증·8개 표시로 성공했다(13.903초). 실패·재실행 성공 원본을 모두 보존한다. 이는 해당 오류가 외부 서비스의 일시 응답이었음을 뒷받침하며 장애가 재발하지 않는다는 보장은 아니다.


## 2026-10-29 YouTube 재생 연결 개선

기존 에뮬레이터에는 재생 검색이 없는 이전 앱이 설치되어 있었다. 최신 앱과 서버를 반영하고 기존 데이터·세션을 보존했다. YouTube 공식 채널 영상의 번역된 제목은 설명 첫 줄의 원어 제목도 대조한다. 검색은 최대 50개 후보를 확인한다. 곡명·가수가 정확히 일치하지만 채널이 가수·VEVO·Topic 등으로 확인되지 않은 경우 제목과 채널을 표시하고 사용자의 확인을 받은 뒤 플레이어를 연다. 다른 곡·커버·라이브 등은 제외하며 미검증 후보는 캐시하지 않는다. 해당 후보는 명시적으로 요청한 새 앱에만 반환하여 구버전이 확인 없이 자동 재생하지 않도록 한다.

서버 전체 65개 검사 중 62개 통과·실패 0·3개 제외, 별도 빈 API37 기기의 Android 재생 정책 검사 6개 통과. 기존 사용자 계정을 연결한 앱에서 ‘ポリリズム’의 실제 공식 영상과 IFrame 플레이어 준비를 확인했다. 사용자 확인이 필요한 ‘Make you happy’의 실제 JYP 채널 후보도 YouTube API에서 재생 가능 상태를 확인했다. IFrame 안의 재생 버튼 클릭·실휴대폰은 확인하지 않았다. 서버의 YouTube API 키가 없어 실제 검사는 연결한 사용자 계정으로 수행했다. 키를 서버에 설정하면 사용자별 YouTube 연결 없이 검색할 수 있다. 최신 노션은 연결 불가로 확인하지 못했다. 원본 결과는 `output/fixes/youtube-playback/2026-10-29/`에 있다.


## 2026-10-29 영상 댓글 시간표

영상 설명에 시간표가 없을 때 YouTube Data API의 관련도순 상위 최상위 댓글 최대 100개를 확인한다. 두 개 이상 유효한 시간·곡명이 있는 댓글 중 가장 많은 시간표를 가진 댓글 하나를 가져오며 댓글을 서로 합치지 않는다. 검토 화면은 댓글 출처를 알리고 시간·곡명·아티스트를 수정할 수 있다. 댓글 조회 실패는 찾지 못한 경우와 구분한다. 직접 입력은 댓글 조회를 하지 않는다. 답글이나 100개 이후 댓글은 조회하지 않는다.

요청 영상 `VtJ_2SbYoIM`은 실제 연결된 YouTube 계정으로 댓글에서 7개 항목을 찾았다. 설치된 앱에서도 댓글 안내와 첫 곡 Paul Blanco / Summer의 검토 화면을 확인했다. 서버 66개 검사 중 63개 통과, 3개 제외, 실패 0개. Android 디버그 앱 빌드 성공. 기존 데이터와 계정을 보존하며 서버와 앱을 갱신했다. 테스트 산출물은 `output/fixes/youtube-comment-timeline/`에 있다. 최신 노션은 연결 불가로 확인하지 못했다.


## 2026-10-29 YouTube 앱 내 재생 보강

재생할 수 없게 된 캐시 영상을 제거한 뒤 다시 검색하며, 확인된 영상이 임베드 불가일 때 사용자 확인이 필요한 재생 가능 후보를 우선한다. 곡명·아티스트가 포함된 음악 영상에 추가 표기가 있어도 후보를 표시하되 사용자 확인을 거친다. 커버·라이브 등은 제외하며, 구버전 앱에는 미확인 후보를 반환하지 않는다. 429·5xx 일시 오류에는 앱 내 재시도를 제공한다.

실제 YouTube에서 무작위 20곡 중 19곡은 임베드 가능한 후보를 찾았고 나머지 1곡은 요청 제한 429였다. 다른 8곡도 8개 후보를 확인했으며, 이 중 기존에 실패했던 Rising Hope는 실제 앱에서 사용자 확인 후 플레이어가 준비됐다. 서버 68개 검사 중 65개 통과·3개 제외·실패 0개, 별도 기기에서 429 후 재시도 검사 1개 통과. 증거는 `output/fixes/youtube-playback/coverage-2026-10-29/`에 있다. 이번 실제 검사는 연결된 사용자 YouTube 계정으로 진행했으며 서버 YouTube API 키는 아직 미설정이다. 실휴대폰과 모든 곡의 일치 여부는 검증하지 않았다.


## 2026-10-29 YouTube 대체 영상 선택

첫 후보가 원하는 영상이 아니어도 앱 안에서 재생 가능한 다른 후보를 선택할 수 있다. 후보는 곡명과 가수 일치 여부와 영상 상태를 확인하며, 미확인 후보는 사용자 선택을 필요로 한다. 답변은 이전 앱이 이해할 수 있는 첫 후보 형식을 유지하며 구버전에는 미확인 후보를 반환하지 않는다. 별도 기기의 다른 영상 선택 UI 검사와 실제 YouTube 8곡 조회, 서버 전체 검사를 수행했다. 실제 테스트는 연결된 사용자 YouTube 계정을 사용했고 서버 YouTube API 키와 실휴대폰은 확인되지 않았다. 자세한 검사 범위와 결과는 `output/fixes/youtube-playback/alternatives/verification.json`에 있다.
