MODULES & BOUNDARIES

IDENTITY & PERSISTENCE

소유자 중심의 데이터 관계

클릭한 테이블의 실제 스키마를 아래에서 확인할 수 있습니다. 목록과 반응, 서비스 토큰, 공개 스냅샷은 각각 다른 목적과 삭제 경계를 가집니다.

기기 저장소와 서버 저장소

서버 연결 전에는 SQLite의 feedback, playlists, items를 사용합니다. 서버에 연결하면 현재 앱 세션의 서버 데이터로 전환하며 자동 병합하지 않습니다. 서버 주소·계정이 바뀌면 이전 요청의 재시도가 다른 소유자에게 쓰지 못하도록 차단합니다.

신규 카카오 사용자의 첫 계정 등록은 현재 익명 소유자의 데이터를 이어받습니다. 이미 존재하는 카카오 계정에 로그인할 때는 해당 계정의 데이터를 사용하며, 같은 이메일을 근거로 다른 계정을 자동 병합하지 않습니다.
END-TO-END

실제 요청이 지나가는 순서

시작 버튼부터 외부 확인·DB 반영·결과 응답까지 추적합니다. 공급자 토큰, 앱 세션, 외부 작업 ID는 서로 다른 역할을 맡습니다.

HTTP CONTRACT

현재 서버의 API 계약

현재 컨트롤러의 HTTP 메서드와 경로를 추출했습니다. 재생 상태·계정 삭제 안내·공개 목록 안전 기능을 포함하며 입력·오류 계약은 연결된 소스를 확인할 수 있습니다.

현재 소스의 HTTP 라우트 · 입력/출력 DTO의 상세는 연결한 컨트롤러 소스
메서드경로담당 영역 / 설명소스

계약에서 반복되는 규칙

  • 개인 데이터는 Bearer 앱 세션으로 소유자를 확인합니다. 공개 안내·공개 목록 읽기는 허용된 비로그인 경로입니다.
  • 생성·가져오기·전송 UUID를 같은 요청의 재시도에 사용하여 응답 유실 후 중복 작업을 방지합니다.
  • 부정확한 입력은 400, 인증/소유권은 401·403·404, 충돌은 409, 본문 초과는 413, 요청 한도는 429·Retry-After, 연결 실패는 안전한 오류로 표시합니다.
  • 곡 저장의 출처 스냅샷과 외부 작업 기록을 구분하여 카탈로그가 바뀌거나 원본 정보가 만료되어도 저장 행동을 다른 용도로 재해석하지 않습니다.

설정하고 실행하는 순서

  1. Android 프로젝트는 android/, 서버는 backend/, 공통 로직은 core/입니다.
  2. 비공개 설정 예제에 키·앱 ID·암호화 키·DB·콜백을 입력합니다. 카카오 네이티브 키는 빌드 후 APK에 반영됩니다.
  3. 서버는 backend/에서 실행합니다. 개발 기본 주소는 127.0.0.1:8080, DB는 파일 H2입니다.
  4. 실제 배포는 PostgreSQL15와 Caddy HTTPS 구성을 사용합니다. 데이터 이전과 기존 암호화 키 보존은 별도 작업입니다.
  5. 실제 제공자 승인·휴대폰·공개 링크를 확인해야 공개 실행의 성공이라고 기록할 수 있습니다.
