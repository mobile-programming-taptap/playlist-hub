# TapTap

Java Android 음악 추천·플레이리스트 앱. 2026-10-19에 다시 확인한 [노션 명세](https://app.notion.com/p/3ed64b5ce98380b8b96ad80157bff1dd)와 사용자의 추가 요구에 맞춰 자연어 추천·반응·카드 탐색·재생·내 목록, 영상 변환·플랫폼 이전·매칭 검토, 계정·대화 조정·공개 목록을 구현하고 검수한다. Apple Music은 지원 범위에서 제외했다. 현재 목표는 출시할 수 있는 품질의 구현과 검수이며 실제 공개 배포·스토어 출시는 포함하지 않는다. 카카오톡·카카오계정 로그인과 기존 목록 소유권 보존을 지원한다. 설정과 실제 서비스 승인·검증 범위는 [카카오 로그인 설정](docs/kakao-login.md), [전체 기능 기록](docs/full-feature-status.md)에 구분한다.

구현 정리: [대화형 구현 지도](docs/implementation.html) · [기계 판독 인벤토리](docs/implementation-inventory.json) · [검증 범위](docs/tests-and-evidence.md). 2026-10-19 최종 소스와 기록된 검사 범위를 표시하며 과거 빌드 근거는 날짜·해시를 유지한다. HTML 파일은 오프라인으로 기능·구조·데이터·API·실행 흐름·화면을 탐색할 수 있다.

## 추천 안정화 · 2026-10-27

현재 실행용 서버는 `output/server/taptap-backend.jar`다. 구버전의 고정 장르 제한을 제거한 최신 소스에, 발매 원문 곡명·가수 표기 보존, MusicBrainz 502/503/504 한 번 재시도(초당 한 요청·전체 12초 제한), 검색 응답 최대 4MB, 검증 탈락으로 7곡 미만일 때 다른 AI 후보를 한 번 보충하는 처리를 적용했다. 보충도 별도 AI 호출 한도를 사용하며 전체 처리 예산은 30초다. 확정된 원래 조건·유지곡·제외곡은 보존하고, 보충 실패 시 먼저 검증된 결과를 유지한다. 검증하지 못한 곡이나 고정 카탈로그로 수를 채우지 않는다.

`output/release-quality/`의 10월19일 파일은 당시 검수본으로 보존한다. 현재 수정본의 검사와 파일 식별값은 `output/checks/recommendation-reliability/`에 별도 기록한다. 외부 서비스 실패를 완전히 없앨 수는 없으며, 곡 수는 실제 검증·사용자 조건·반응에 따라 적을 수 있다. 적은 결과 안내는 후보 검증 수와 최종 추천 수를 구분한다.

## 실행

Android Studio에서 `android/`를 연다. `core/`, `catalog/`는 같은 상위 폴더에 두어야 한다. Android 7.0 이상에서 설치 가능하다. 새 자연어 추천은 OpenAI가 설정된 서버에 연결해야 한다. 연결 전에는 기기에 저장한 목록을 열 수 있고, 요청 초안을 보존하여 연결 후 다시 요청할 수 있다. 고정 곡 목록으로 추천을 대신하지 않는다. 반응·목록은 기기의 SQLite에 보관한다. 앱 삭제 시 기기 데이터도 삭제된다.

```sh
cd android
./gradlew :app:assembleDebug :core:checkRecommendations
```

백엔드는 Java 21 이상으로 실행한다. 기본 DB는 파일 H2이며 `backend/data/`에 보관된다. 기본 바인딩은 로컬 `127.0.0.1:8080`이다.

```sh
cd backend
../android/gradlew bootJar
java -jar build/libs/taptap-backend.jar
```

서버는 `backend/`를 현재 폴더로 실행한다. `.env`와 `data/`의 상대 경로가 이 폴더를 기준으로 정해진다. 개발 중 바로 실행하려면 같은 폴더에서 `../android/gradlew bootRun`을 사용할 수 있다.

앱 설정에서 `http://10.0.2.2:8080`을 입력하면 Android 에뮬레이터가 로컬 서버에 연결된다. 서버의 곡·반응·저장 상태를 모두 확인한 뒤 연결 설정을 바꾼다. 중간 조회가 실패하면 기존 저장소와 데이터를 유지하고 주소를 고쳐 같은 창에서 다시 연결할 수 있다. 서버 연결 시 서버의 별도 반응·목록을 사용한다. 기기에 저장한 데이터와 자동 합치지 않는다. 연결을 해제하면 기기의 반응·목록을 다시 사용한다. 저장소가 바뀐 상태로 화면이 재생성되면 이전 저장소의 추천 결과와 목록 위치를 복원하지 않는다. 초기 서버 데이터 조회가 실패하면 추천·반응·추천 곡 저장·교체를 비활성화하고 설정에서 재연결이나 기기 목록으로 전환를 제공한다.

Android 17 이상에서 로컬 서버를 연결할 때 [로컬 네트워크 권한](https://developer.android.com/privacy-and-security/local-network-permission)을 요청한다. 권한창에서 화면이 재생성돼도 연결하려던 서버 주소와 허용 결과를 이어받는다. 복원된 과거 응답보다 현재 기기의 권한 상태를 우선하여 이미 허용된 연결을 잘못 해제하지 않는다. 새 서버의 권한을 거부하면 기존 저장소를 유지하고, 사용 중인 로컬 서버의 권한을 거부하면 해당 주소를 해제한 뒤 기기의 목록으로 전환한다. 서버 세션은 보관하여 다시 연결할 수 있다. 공개 HTTPS 서버 연결에는 이 권한을 요청하지 않는다.

실제 휴대폰은 HTTPS 서버 주소를 사용한다. 개발 중 LAN 테스트만 `SERVER_ADDRESS=0.0.0.0`과 개발 PC의 사설 IP를 사용한다. HTTP 테스트 연결은 디버그 앱에서만 허용된다.

서버의 `/`는 앱 소개, `/privacy`는 데이터 처리 안내, `/account-deletion`은 계정 삭제 방법을 로그인 없이 제공한다. `SUPPORT_EMAIL`에 실제 운영자 이메일을 설정하면 문의와 외부 삭제 요청용 메일 작성 링크를 표시한다. 사용자가 메일을 보내야 하며 링크를 여는 것만으로 요청이 접수되거나 계정이 삭제되지는 않는다. 주소가 없으면 외부 요청 창구를 사용할 수 없다고 안내하며 앱 안의 본인 삭제 기능은 계속 제공한다. 운영자는 요청자 소유권을 확인해야 하며 비밀번호·인증 코드·토큰을 메일로 요청하지 않는다. 실제 운영자 정보·공개 도메인·음악 서비스 승인은 별도로 확인해야 한다. 공개 설정 절차는 [배포 안내](docs/deployment.md)를 따른다.

서버 연결 전에 개인정보·외부 음악 서비스 처리 안내에 동의한다. 동의는 서버 주소와 안내 버전별로 기기 안에 보관하며, 거절하면 기기 목록 모드로 돌아간다. 건강 확인을 제외한 서버 요청은 동의 후에만 실행한다. 계정 설정에서 개인정보 안내·계정 삭제·도움말·라이선스·문의와 앱 버전을 확인할 수 있다.

## OpenAI

서버 환경에 `OPENAI_API_KEY`를 설정하거나 `backend/.env`에 `OPENAI_API_KEY=발급받은키` 한 줄을 저장한다. 서버를 `backend/`에서 실행하면 이 파일을 자동으로 읽으며 변경 후 재시작한다. `.env`는 Git에서 제외한다. 키는 앱·저장소·로그에 넣지 않는다. 기본 모델은 `gpt-5.4-mini`이며 `OPENAI_MODEL`로 바꿀 수 있다. OpenAI [Responses API](https://developers.openai.com/api/docs/guides/migrate-to-responses), [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)를 사용한다.

AI는 사용자가 직접 작성한 500자 이하의 요청, 이전 요청 최대 8개, 검증된 조건 스냅샷과 앱 내부 좋아요의 허용 태그 수만 입력받는다. 한 번의 응답에서 조건과 실제 발매곡 후보 최대 12개를 제안하고, 서버가 MusicBrainz의 곡명·가수·녹음 ID를 확인한 후보에서 최대 8곡을 추천한다. AI가 제안한 곡명은 검증 전까지 추천에 사용하지 않으며 ID와 URL은 AI에게 생성시키지 않는다. 확인한 곡은 별도 DB 카탈로그에 보관해 저장·좋아요·곡 교체·이어서 요청·재시작에도 사용한다. 가져온 플랫폼 곡·외부 열기 기록·저장 행동은 AI에 보내지 않으며 `store: false`로 요청한다.

장르와 곡 언어를 고정 목록으로 제한하지 않는다. 익숙한 장르·분위기·악기 별칭은 유지하고 새 장르는 `genre:<slug>`로 표현한다. slug는 영문 소문자·숫자로 시작하는 최대 64자의 영문 소문자·숫자·밑줄·하이픈이며, 긍정·제외 태그 목록은 각각 최대 64개다. 곡 언어는 2~3자 기본 코드와 선택적인 하위 코드로 구성된 최대 35자의 ISO/BCP 계열 문법을 사용하고, 빈 값은 미지정, `none`은 연주곡이다. 이는 입력 문법 검증이며 모든 코드의 등록 여부나 분류의 정확성을 보증하지 않는다. 프랑스어와 일본어 등 서로 다른 언어는 구분하며 여러 언어의 긍정·제외가 섞이면 검증된 모델 해석을 보존한다. 장르명이나 가수 국적만으로 곡 언어를 지정하지 않는다.

가수·상황과 임의 장르의 의미는 OpenAI가 후보 생성·분류에 반영한다. 새 후보와 기존 검증곡 캐시 모두 같은 조건 표현을 사용하며 저장한 목록의 곡 스냅샷은 유지한다. 후보의 장르·분위기·언어는 AI 분류이고, MusicBrainz가 확인하는 범위는 녹음의 실재·곡명·가수 정보다. 모든 자연어 요청의 음악적 적합성을 검증했다는 뜻은 아니다. 조건에 맞는 검증곡이 없으면 부족 안내를 표시하며 다른 장르나 고정 곡으로 채우지 않는다. 곡 교체도 다른 현재 곡을 유지하고 바꿀 곡을 제외한 새 AI 요청을 실행한다.

MusicBrainz 확인은 후보들을 한 번의 검색으로 묶는다. 검색 전체는 잠금 대기·호출 간격·본문 수신·한 번의 일시 오류 재시도를 포함해 12초, 잠금 진입 대기는 최대 2초로 제한하며 원격 응답에는 남은 시간 안에서 최대 6초를 준다. 호출 간격은 서버 인스턴스 안에서 1초 이상이다. OpenAI 응답은 100,000바이트, MusicBrainz 응답은 4,000,000바이트를 넘기기 전에 읽기를 중단하고 헤더 뒤 멈춘 본문에도 마감 시간을 적용한다. Android의 추천 POST 응답 대기는 35초이며 다른 서버 요청은 22초다. 지연·과부하에도 다른 곡으로 대체하지 않는다.

키가 없거나 연결 실패·잘못된 응답·곡 검증 서비스 실패는 503, 호출 한도 초과는 429로 원인을 안내한다. 고정 목록이나 기존 카탈로그의 다른 곡으로 대체하지 않는다. 검증된 후보가 없으면 빈 결과와 같은 요청으로 재시도할 안내를 반환한다. 사용자가 직접 유지한 곡만 새 조건과 관계없이 보존한다. AI 호출은 사용자당 1시간 20회, 서버 전체 UTC 하루 200회를 기본 상한으로 삼으며 시도도 횟수에 포함한다. `AI_USER_HOURLY_LIMIT`, `AI_DAILY_LIMIT`로 조정한다. 실제 과금 상한은 OpenAI 프로젝트의 예산·권한 설정도 적용한다.

이전 40곡 한정 추천의 실제 OpenAI 9회 검사는 이전 호출 기록 (로컬 기록: `output/checks/openai-full.json`)에 해당 빌드의 근거로 보존한다. 이후 새 카탈로그와 당시 35종 장르 확장 검사는 [기능별 상태](docs/full-feature-status.md), `output/checks/dynamic-recommendations/`, `output/checks/genre-expansion/`에 남아 있다. 현재의 임의 장르·언어 표현과 제한 시간 변경을 실제 OpenAI로 재검증한 기록은 아니다. 현재 구조에서도 의미 해석과 음악 분류는 모델에 의존하며 녹음 정보 검증과 구분한다.

## 저장·인증

서버는 앱 설치별 익명 세션을 발급한다. 32바이트 난수 토큰은 기기의 비공개 설정에, SHA-256 해시만 DB에 보관한다. 사용자 입력으로 소유자를 지정하지 않으며 모든 목록 접근을 토큰 소유자로 확인한다. 카카오톡이 설치돼 있으면 카카오톡으로 로그인하고, 없거나 사용이 불가능하면 카카오계정 브라우저 로그인으로 이어진다. 명시적으로 취소하면 기존 계정 상태를 유지한다. 서버는 카카오 토큰의 앱 ID·만료·사용자 ID를 공식 API로 확인한 뒤 자체 세션을 발급한다. 처음 가입하면 익명 목록·반응을 같은 소유자에 이어받고, 기존 카카오 계정은 그 계정의 서버 데이터를 복원한다. 이메일이 같다는 이유로 계정을 합치지 않는다. 기존 이메일·15자 이상 비밀번호 로그인도 보조 경로로 유지한다. 로그인은 기기마다 별도 세션을 발급하며 같은 계정으로 다른 기기에 로그인하면 서버의 목록·반응·즐겨찾기를 함께 사용할 수 있다. 비밀번호는 무작위 salt와 PBKDF2-SHA256으로 보관한다. 로그아웃은 해당 기기 세션만 제거하고 카카오 계정 삭제는 동일 카카오 계정을 다시 인증한 뒤 계정과 소유 데이터를 삭제하고, 이메일 계정은 현재 비밀번호를 확인한다. 카카오 SDK 토큰은 서버 DB나 앱의 자체 설정에 저장하지 않는다. 앱 로그아웃은 해당 TapTap 세션과 SDK 캐시를 정리하며 카카오톡 앱 자체를 로그아웃시키지 않는다. 앱을 삭제하면 기기의 세션 연결 정보도 삭제된다.

설정·토큰·기기 DB는 클라우드 백업과 기기 간 이전에서 제외한다. Android 12 이상은 일부 기기에서 `allowBackup=false`만으로 기기 이전이 제한되지 않아 [백업 제외 규칙](https://developer.android.com/identity/data/autobackup)을 함께 적용한다.

가입 계정의 기기별 세션은 발급 후 30일에 만료된다. 만료된 세션만 거절·제거하고 계정 데이터와 다른 기기의 유효한 세션은 보존한다. 앱은 만료 시 다시 로그인을 안내한다. 익명 서버 세션에는 같은 자동 만료를 적용하지 않으며 가입하지 않아도 계정 화면에서 본인의 익명 서버 데이터와 세션을 삭제할 수 있다. 가입 계정 삭제에는 기존과 같이 비밀번호 또는 같은 카카오 계정의 재인증이 필요하다. 서버 삭제는 다른 소유자와 기기에만 저장한 목록을 삭제하지 않는다.

이름 생성·변경에 실패하면 입력한 이름을 유지하고 해당 입력창과 대화상자 안에 오류를 표시한다. 오류 후 초점을 옮겨 Android 7에서 말풍선이 재시도 버튼의 터치를 가로채지 않도록 한다. 처리 중에는 이름 입력과 제출 버튼을 잠시 비활성화하고 실패하면 같은 창에서 다시 시도할 수 있다. 새 목록을 만든 뒤 곡 저장만 실패하면 생성한 목록을 유지하고 같은 목록으로 저장을 재시도한다. 서버에 목록이 만들어졌지만 응답이 끊긴 경우에도 같은 창에서 다시 시도하면 목록이 중복 생성되지 않는다. 생성 응답을 확인하기 전에 이름을 바꿨는데 이미 저장된 이름과 다르면 원래 이름으로 다시 시도하도록 안내한다. 곡 검색에서 동작을 선택하면 검색창을 닫아 저장 완료·실패 안내가 뒤에 가려지지 않게 처리한다.

같은 목록에 같은 곡을 재시도해도 한 번만 저장한다. 목록 생성·조회·상세·이름 변경·목록 삭제·곡 제거·곡 순서 변경을 지원한다. 곡 메뉴의 위로·아래로 이동으로 순서를 저장한다. 삭제 전 목록 이름과 곡 수를 확인한다. 내 목록 이름 검색과 검증된 카탈로그의 곡명·아티스트 검색을 지원한다. 검색·순서 변경·저장은 추천 반응으로 기록하지 않는다. 음원 파일은 저장하지 않는다. 영상 설명 시간표를 검토·수정·제외해 별도 외부 곡 항목으로 저장하고, 플랫폼 목록 가져오기·곡 후보 확인·명시적 전송·부분 실패 재시도를 지원한다. 외부 항목은 추천 카탈로그에 등록하지 않는다.

생성 API `POST /playlists`는 이름 `title`과 선택적인 소문자 UUID `id`를 받는다. 같은 소유자·ID·이름의 재요청은 서버 재시작 후에도 기존 목록과 현재 곡 수를 반환하며, 목록 100개 상한에서도 재시도가 가능하다. 다른 소유자의 ID는 404, 같은 ID의 다른 이름은 409, 잘못된 ID는 400으로 거절한다. ID를 생략한 기존 클라이언트도 계속 지원한다.

관리 API: `PUT /playlists/{id}`(title), `DELETE /playlists/{id}`, `PUT /playlists/{id}/items/order`(itemIds). 순서 요청은 해당 목록의 모든 항목 ID를 정확히 한 번씩 지정하며 트랜잭션으로 저장한다. `GET /playlists?q=...`, `GET /catalogue?q=...`는 100자 이하 검색어를 받는다. 검색은 대소문자·유니코드 호환 문자 차이를 정규화하고 모든 검색 단어를 확인한다.

목록에 추가할 때 곡 정보와 출처를 함께 보관하여 카탈로그가 변경되어도 저장한 곡 정보를 유지한다. 목록 상세와 스크롤 위치는 화면 재생성 후 복원한다. 진행 중인 반응·목록 작업도 완료까지 유지하고 새 화면에서 최신 상태와 오류를 확인한다. 새 목록 생성과 첫 곡 저장은 화면 재생성과 관계없이 이어 실행한다. 화면 종료 시 열려 있는 대화상자를 닫아 이전 창이 새 화면의 입력을 가로채지 않도록 한다. 서버의 목록 제목·곡은 한 번에 조회하여 동시 삭제 중 빈 목록으로 잘못 표시하지 않는다. 삭제 후 응답이 끊겨 다시 시도한 경우 이미 삭제된 목록은 목록 화면으로 복구한다. 연결 모드를 바꾼 뒤 이전 실패의 재시도로 다른 저장소에 쓰지 않는다.

상세의 ‘목록 텍스트 공유’는 순서대로 곡명·아티스트·검증된 YouTube Music 링크(없으면 출처 링크)를 Android 공유 화면에 전달한다. 사용자가 공유 대상을 고른다. ‘공개 설정 · 공유 링크’에서 목록을 직접 공개하면 읽기 전용 웹 링크를 공유할 수 있다. 비공개로 바꾸면 기존 링크가 즉시 닫힌다. ‘발견’에서 100자 이하 공개 목록 검색·즐겨찾기·복사·앱 즐겨찾기 수에 따른 순위를 제공한다. 변환 저장·공개 목록 복사 후 ‘내 목록으로’를 선택하면 서버·계정을 확인해 실제 저장한 목록 상세를 연다. ‘계속 보기’나 일반 뒤로 가기는 이전 화면을 유지한다.

공개 전에 현재 게시 규칙을 확인하고 동의한다. 공개 목록·작성자를 신고하거나 작성자를 차단하고 차단 목록에서 해제할 수 있다. 신고는 500자 이하, 본인당 24시간 새 신고 10건이며 같은 대상 재시도는 기존 신고로 처리한다. 접수는 자동 숨김이나 처리 완료를 뜻하지 않는다. 차단은 본인의 발견·검색·순위·즐겨찾기·상세·복사에 적용하며 이미 복사한 목록이나 비로그인 웹 전체를 삭제하지 않는다. 별도 운영자 인증의 신고 검토 API가 기각·숨김을 처리한다. 숨긴 원본 목록은 공개 링크와 재공개를 제한하며 작성자 신고의 숨김은 당시 공개 목록들에 적용한다. 운영 설정은 [배포 안내](docs/deployment.md)에 있고, 최종 검수 범위와 실제 운영 승인은 아래 기록에서 구분한다.

추천 결과의 ‘추천 N곡 모두 저장’으로 현재 추천을 기존 목록 또는 새 목록에 한 번에 담을 수 있다. `POST /playlists/{id}/items/batch`는 `trackIds`로 서로 다른 1~10곡을 받는다. 기기와 서버 모두 일괄 저장을 트랜잭션으로 처리하므로 일부 곡만 저장되는 실패를 방지한다. 같은 추천을 다시 저장해도 목록의 곡이 중복되지 않는다.

PostgreSQL을 사용할 때 `DATABASE_URL`을 JDBC URL로, `DATABASE_USER`, `DATABASE_PASSWORD`를 환경에 설정한다. 동일한 SQL 스키마를 사용한다. 이전 빌드의 H2·PostgreSQL 15 저장·소유권·중복 방지·목록 순서·동시 조회/삭제·재시작 근거는 기록된 빌드에 한정한다. 현재 단일 서버에서는 소유자별 잠금으로 외부 서비스 작업과 로그아웃·삭제를 조정한다. 잠금은 64개 묶음으로 제한하므로 다른 소유자도 같은 묶음에서는 기다릴 수 있다. 여러 서버로 확장할 때는 DB 쓰기·호출 상한·원격 작업의 분산 조정이 필요하다. 호출 한도는 ISO 시간 기록을 `Instant`로 비교한다.

JSON 파싱과 DB·외부 호출 전에 요청 본문을 512KiB로 제한하며 초과 시 413을 반환한다. 접속 주소별 기본 상한은 전체 요청 240회/분, 세션 발급 30회/시간, 추천 요청 60회/시간, 가입·로그인 10회/분, 플랫폼 조회·매칭·변환·재생 상태 확인 20회/분이다. 상한 초과는 429와 `Retry-After`로 안내한다. 주소별 카운터는 서버 프로세스 메모리에 있으므로 재시작 때 초기화되며 다중 서버에는 공유 제한 장치가 필요하다. 별도로 DB에 보관하는 AI 사용자별·전체 호출 상한도 함께 적용한다.

## 추천 화면·수정

프로젝트 세션의 `output/pdf/TapTap_모바일_UIUX_레퍼런스.pdf` 2~3쪽 시안과 사용자가 첨부한 Swipefy 화면을 참고한다. 작은 중앙 제목 아래 큰 실제 영상 썸네일을 배치하고, 사진에서 얻은 색을 따뜻한 배경에 반영한다. 곡명·아티스트·추천 이유는 모서리가 8dp로 둥근 차콜색 겹침 카드에 표시한다. 하단에는 선택 탭을 형광색으로 강조하는 ‘추천’·‘변환’·‘발견’·‘내 목록’·‘계정’ 다섯 탭을 제공한다. 좌우 스와이프와 하단에 고정한 검정 원형의 이전·싫어요·재생·좋아요·다음 버튼으로 탐색한다. 싫어요는 코럴, 좋아요는 초록, 재생은 흰색으로 구분한다.

카드의 곡 수정 아이콘·‘다른 앱’·‘목록에 저장’과 요청 수정·모두 저장을 제공한다. 버튼의 실제 터치 영역은 48dp 이상이며 줄바꿈과 Android 기본 세로 스크롤을 적용한다. 좁은 화면이나 큰 글씨에서는 카드와 카드 바깥의 추천 화면을 스크롤해 곡 정보·요청 수정·전체 저장에 접근한다. 반응·탐색 바는 추천 스크롤 바깥에 고정한다. 되돌리기·재시도·저장 안내는 보이는 반응 바 또는 하단 메뉴 위에 표시해 시스템 버튼에 가려지지 않게 처리한다. 변환·발견·계정과 대화상자에도 같은 차콜·라임·Pretendard 톤을 적용한다. 변환·플랫폼 연결·공개 목록은 각 탭에서 실제 기능 화면으로 이어진다.

앱 글꼴은 [Pretendard 1.3.9](https://github.com/orioncactus/pretendard/releases/tag/v1.3.9)를 사용한다. 본문은 Regular, 제목·버튼은 SemiBold, 목록 제목은 Bold로 구분한다. 정적 폰트와 SIL Open Font License 원문을 앱에 포함하므로 인터넷 없이도 같은 글꼴을 표시한다. Android 7에서도 AppCompat 경로로 입력창과 대화상자에 적용한다.

추천 입력은 제목을 입력칸 위에 따로 표시하고 크림색 둥근 입력칸·16dp 내부 여백·어두운 글자 수 표시를 사용한다. 제목을 입력란과 접근성으로 연결하며, 입력 중에는 테두리 위에 작은 제목을 겹치지 않는다. 500자 제한·오류 안내·요청 수정·초안 복원을 유지한다.

결과에 실제 해석된 조건을 표시한다. ‘요청 수정’으로 직접 요청을 고친 뒤 다시 추천받을 수 있다. 카드의 ‘곡 수정’에서 같은 조건의 다른 곡으로 바꾸거나 이번 결과에서만 제외하고 되돌릴 수 있다. 현재/이미 제외한 곡은 교체 후보에서 빼고 기존 좋아요·싫어요를 유지한다. 교체는 다른 현재 곡을 유지하고 교체할 곡을 제외하는 새 AI 요청으로 처리하며, 새로 검증된 후보를 사용한다. 임시 제외는 영구적인 싫어요로 저장하지 않는다. 조건·수정 결과와 아직 제출하지 않은 요청 초안은 화면 재생성 후 복원한다. 화면을 다시 만들 때 진행 중인 추천을 유지하여 같은 AI 요청을 다시 보내지 않으며, 새 추천은 첫 곡부터 표시한다. ‘이어서 요청 · 곡 유지’는 이전 조건을 유지하며 최신 요청으로 분위기·장르·언어를 바꾸고 직접 선택한 곡을 남긴다. 장르의 유지·교체·제외에도 같은 조건 규칙을 적용한다. 직접 유지한 곡은 새 조건과 관계없이 남기며, 유지곡이 8곡이어도 새 장르의 곡을 찾지 못한 사실을 별도로 안내한다. 싫어요 곡은 유지할 수 없다. 이전 요청 표시가 8개를 넘어도 검증된 조건 스냅샷으로 조건을 유지한다. 운영체제가 앱 프로세스를 종료한 경우 같은 요청·유지/제외 곡을 보관하고 직접 재시도하며 자동 재전송하지 않는다. 재시도는 서버와 계정 소유자가 같은 경우에만 허용한다. 화면을 바꾸면 입력 키보드를 닫고, 순번과 플레이어 상태 변경을 화면 읽기에 전달한다.

## 영상 변환·플랫폼 연결

목록 만들기는 영상 시간표와 음악 서비스 가져오기를 각각 카드로 나눠 표시한다. 입력 제목과 둥근 입력칸, 강조한 확인·가져오기 버튼, 상단 기록 메뉴를 제공한다. 하단 메뉴는 균일한 아이콘·글자와 선택 표시를 사용하며 큰 글씨를 지원한다.

‘변환’에서 YouTube 원본 URL만 입력하고 ‘영상에서 곡 목록 가져오기’를 누르면 공식 API로 영상 제목·설명·길이를 조회한다. 서버의 `YOUTUBE_API_KEY` 또는 연결된 YouTube 계정이 필요하다. 직접 붙여넣기는 ‘직접 시간표 입력’으로 펼치는 보조 경로이며 별도 버튼으로 제출한다. 자동 버튼은 수동 초안이 남아 있어도 설명을 조회한다. 설명에서 시간표를 찾지 못하면 주소를 유지하고 직접 입력을 펼친다. 시간표는 최대 100행·영상 최대 6시간을 지원하며, 잘못된 시간·중복·누락된 곡 정보는 검토 대상으로 남긴다. 영상 길이 값 0 또는 -1은 미상으로 처리한다. 길이를 알면 종료 시각보다 작은 시작 시각만 허용하고, 미상이면 시작 시각의 6시간(21,600초) 포함 상한을 검증한다. 사용자가 곡명·아티스트·시작 시간을 고치거나 행을 제외한 뒤 저장한다. 원본 영상의 해당 위치를 공식 플레이어 또는 브라우저로 열며 음원 추출이나 곡 추측은 하지 않는다.

Spotify·YouTube Music 연결은 각각 개발자 앱 설정이 필요하다. [서버 환경 템플릿](backend/.env.example)의 항목을 비공개 `backend/.env`에 설정한다. 암호화 키 `PLATFORM_TOKEN_SECRET`은 32바이트 난수의 Base64 값이며 저장된 연결을 읽을 때 필요하므로 유지한다. Spotify/Google은 한 번만 사용하는 state·PKCE·세션 결속을 적용한다. 플랫폼 토큰은 AES-GCM으로 암호화하며 앱이나 공개 응답에 전달하지 않는다. 설정이 없는 플랫폼은 계정 화면에서 사용 불가와 ‘필요한 연결 설정 확인’을 표시하며, 연결 시작 오류에서도 확인이 필요한 설정 이름을 안내한다. 반복 실패해도 재시도 버튼은 하나만 표시한다.

OAuth 복귀는 `taptap://connected`의 성공·취소·실패를 구분한다. 허용 완료는 `status=connected`, 사용자 거절은 `status=cancelled&reason=access_denied`, 만료·재사용·다른 세션의 state는 `status=error&reason=session_expired`다. 제공자 오류는 `provider_unauthorized`, `provider_forbidden`, `provider_rate_limited`, `provider_unavailable`, `connection_failed` 중 고정 사유만 전달한다. 인증 코드·state·토큰·제공자 응답 본문은 복귀 주소에 넣지 않는다. 앱은 진행 중인 제공자·서버·계정과 일치하는 복귀만 처리하고 계정 상태를 다시 조회해 실제 연결을 확인한다.

‘내 플레이리스트 선택’에서 연결한 Spotify·YouTube Music 계정이 소유한 목록을 조회하고, 체크한 목록을 각각 내 목록에 가져온다. 목록 이름·곡 수·공개 상태와 선택 수를 표시하며 다음 페이지 조회와 화면 회전에도 선택을 유지한다. 연결을 시작한 화면으로 브라우저에서 돌아오면 계정을 확인한 뒤 목록을 불러온다. 한 번에 20개 선택·화면에 200개 표시를 지원하며 다른 목록은 접힌 ‘링크로 직접 가져오기’에서 가져올 수 있다. 일부 가져오기가 실패하면 완료 목록을 유지하고 남은 작업만 원래 ID로 재시도한다. 앱 프로세스가 종료된 뒤에는 자동 전송하지 않고 저장된 결과에서 명시적으로 이어간다. YouTube Music은 공식 YouTube Data API가 제공하는 본인 소유 플레이리스트 범위이며 좋아요·자동 생성·추천 목록 전체를 제공하지 않는다. 개발자 API 설정 외에 사용자가 Google 계정 연결을 승인해야 비공개 목록에 접근할 수 있다.

공식 API로 읽은 원본 목록을 앱에 별도 항목으로 저장한다. 같은 원본의 반복 곡은 서로 다른 행으로 보존하고, 재시도는 같은 작업 ID를 사용한다. 대상 플랫폼의 ID·ISRC·곡명·아티스트·버전·길이를 비교해 후보를 제시하고, 조회 전·일치 후보 있음·버전 확인 필요·찾지 못함·사용자 제외 상태를 구분해 표시한다. 다음 20곡을 조회해도 앞서 확인한 선택·제외를 보존하며, 일치 후보가 있어도 사용자가 직접 확인해야 한다. 사용자가 각 곡의 후보 또는 제외를 확인해야 새 비공개 플랫폼 목록을 만든다. 전송 결과는 성공·실패·확인 필요·대기를 표시한다. 응답이 끊긴 경우 원격 목록 순서와 작업 표식을 대조하여 중복 추가를 피하고, 남은 곡만 같은 작업으로 이어 보낸다. 작업 기록에서 기존 변환·전송을 다시 열거나 기록만 삭제할 수 있다. 앱 목록을 삭제한 뒤에도 변환 기록에서 같은 원본 목록을 다시 저장할 수 있으며 다른 계정의 목록 ID는 사용할 수 없다. 가져온 목록의 제목·곡·검토 기록은 함께 저장하고 실패하면 함께 복원한다. 변경 반영도 곡·원본 기록·미리보기를 함께 저장하며 실패하면 같은 미리보기로 다시 시도할 수 있다. 저장·변경 반영의 잠금은 실제 commit까지 유지하여 동시 만료 정리·조회와의 잠금 순서를 보존한다.

외부 목록 변경은 ‘목록 변경 미리보기’로 추가·제거·변경을 확인한 뒤 반영한다. 같은 앱 목록에 별도로 저장한 추천곡과 다른 가져오기 원본은 보존한다. 외부 상세 정보는 원본 조회 후 30일 뒤 삭제하고, 제목·곡 수동 수정이나 재저장으로 그 기간을 연장하지 않는다. 최소 원본 참조만 남겨 다시 조회할 수 있도록 하며 공개 스냅샷에서도 만료 정보를 제거한다. 플랫폼 연결 해제는 해당 계정의 플랫폼 토큰·작업·외부 항목과 다른 원본 기록에 남은 해당 플랫폼 후보·선택 정보도 제거한다. 플랫폼 데이터·영상 설명·이미지·연결 기록을 추천 AI나 개인화에 보내지 않는다.

YouTube 목록의 삭제·비공개·잘못된 영상도 원본 행 번호를 유지한 누락 항목으로 기록한다. 전송 재시도에서 원격 목록이 잘렸거나 누락 행·불연속 순서가 있으면 정상적인 앞부분으로 간주해 추가 전송하지 않고 확인 필요 상태로 남긴다. 동일 소유자의 플랫폼 작업은 순서대로 조정하며 전송 실행기는 작업자 2개와 예약 대기열 64개를 사용한다. 실행 예약이 가득 차면 재시도 가능한 결과를 보관하고 503으로 안내한다.

공식 API 계약과 오류 복구는 로컬 응답 서버로 검사한다. 실제 Spotify 개발 모드·Google OAuth 승인·할당량·실계정 전송 성공은 별도 검증이며, 현재 구현 품질 검수에 실제 공개 출시는 포함하지 않는다. 실제 서비스 사용에는 올바른 API·OAuth 설정과 콜백 등록 후 서버를 재시작하고 개발자가 `TAPTAP_API_BASE` 또는 `android/local.properties`의 `taptap.apiBase`로 HTTPS 주소를 지정해 APK를 빌드한다. 사용자는 앱에서 주소를 입력하지 않는다. 최초 이용 동의 후 자동 연결하며, 서버 주소를 변경해 배포할 때는 APK를 다시 빌드한다. API 키만 변경할 때는 서버 재시작으로 적용한다. 팀원끼리 다른 네트워크에서 쓸 때는 [비공개 팀 테스트](docs/team-testing.md)를 따른다. 공개 HTTPS 실행은 [배포 안내](docs/deployment.md)를 따른다.

## 곡 데이터·재생

`catalog/tracks.json`의 40곡은 이전 저장·검색 호환성과 도메인 검사에 쓰는 기본 데이터다. 서버 없이 새 추천을 생성하지 않는다. 서버에 OpenAI가 설정되면 사용자 요청·이전 조건·앱 내 좋아요 태그로 조건과 최대 12개 곡 후보를 한 번에 생성하고, MusicBrainz 공식 검색에서 곡명·아티스트·녹음 ID를 확인한 곡만 최대 8개 추천한다. 새 요청은 검증된 현재 후보에서 고르므로 고정 40곡에 제한되지 않는다. 검증하지 못한 후보는 제외하며 조건에 맞는 결과가 부족하면 안내한다. AI나 검증 서비스 연결이 실패하면 오류와 명시적 재시도를 제공하며 기존 카탈로그 추천으로 대신하지 않는다.

확인된 곡은 `recommendation_tracks`에 보관하여 좋아요·저장·후속 요청·앱 재실행·공개 공유에서 동일한 ID로 사용한다. MusicBrainz의 [핵심 메타데이터 CC0](https://musicbrainz.org/doc/About/Data_License)만 추천 데이터에 사용하며 사용자 태그·평점·가사·음원과 외부 플레이리스트는 추천에 넣지 않는다. 신규 곡의 장르·분위기·상황 태그와 언어는 모델의 분류이며, 곡의 실제 존재 확인과 추천 적합성 평가는 별개다. 임의 장르·언어의 조건은 위의 검증된 태그·코드 문법으로 보관한다. 녹음 정보의 CC0는 표지 이미지의 사용 권리를 보증하지 않는다.

곡 사진은 검증된 YouTube 영상의 실제 썸네일 또는 MusicBrainz가 반환한 발매 ID의 Cover Art Archive 표지를 표시용으로 불러온다. 표지는 해당 서비스와 Internet Archive의 HTTPS 이미지 경로만 제한적으로 따라간다. `maxresdefault`를 우선 조회하고 실패하면 `hqdefault`로 다시 시도하며, 두 시도는 15초의 공통 마감 기준을 사용한다. 8MiB 메모리 캐시로 재사용하고 응답당 2MiB·디코딩 100만 픽셀 상한을 적용한다. 사진과 사진에서 얻은 배경색은 AI 입력이나 추천 근거로 사용하지 않으며 추가 AI 호출도 없다. 실패하면 기본 이미지를 표시하고 추천과 저장은 계속 사용할 수 있다. 카드가 바뀐 뒤 도착한 이전 사진은 적용하지 않는다.

서버가 공식 YouTube 영상 상태를 확인해 해당 영상의 `madeForKids=false`와 `embeddable=true`를 명시적으로 확인한 경우에만 [공식 YouTube IFrame 플레이어](https://developers.google.com/youtube/iframe_api_reference)를 표시한다. 아동용·임베드 불가·상태 미상·설정이나 조회 실패·서버 미연결이면 인앱 플레이어를 만들지 않고 사용자 확인 후 외부 YouTube로 연다. 상태 확인에는 서버 API 키 또는 연결한 YouTube 계정을 사용한다. 사용자가 플레이어의 재생을 눌러야 시작하며 화면 이동·외부 앱 이동·백그라운드 진입 시 종료한다. 앱 ID를 `loadDataWithBaseURL` 출처로 사용해 [공식 클라이언트 식별 요구](https://developers.google.com/youtube/terms/required-minimum-functionality)를 적용한다. 곡의 공식 영상 링크가 없으면 검색으로 연결한다. ‘다른 앱’ 선택창에서 플랫폼 아이콘과 연결 방식을 표시한다. Spotify는 곡명·아티스트 검색, YouTube Music은 검증된 영상 직접 연결을 제공하며 영상 링크가 없으면 검색으로 연결한다. WebView 초기화 실패나 지역·임베드 제한에 따른 재생 실패도 안내와 외부 열기로 복구한다.

영상 ID가 없는 신규 추천곡과 기존 저장곡도 재생 버튼을 누르면 `/playback/tracks/{id}`에서 YouTube 공식 API로 검색한다. 곡명과 아티스트·채널 정보를 비교하여 아티스트/VEVO/Topic 채널 또는 아티스트가 일치하는 자동 생성 발매 영상만 연결하며, 다른 제목·커버·라이브 등 버전이 다른 후보는 자동 선택하지 않는다. API 키가 없으면 요청한 사용자의 연결된 YouTube 계정만 사용한다. 찾은 공개 영상의 ID는 서버 메모리에 최대 256개·24시간 보관하고 재생 상태는 매번 다시 확인한다. 서버 재시작 시 검색 캐시는 사라지며 YouTube 메타데이터는 CC0 추천 카탈로그나 AI 입력에 넣지 않는다. 채널 이름이 다른 공식 배급 영상 등 자동 확인이 어려운 후보는 외부 검색으로 안내하며, 검색 결과 없음과 설정·권한·요청 한도 오류를 구분한다.

카탈로그 재검증: `python3 tools/verify_catalog.py`. 이 작업은 명시적으로 실행할 때만 네트워크를 사용하며 MusicBrainz 요청 간격을 1초 이상 둔다. 동명 코멘터리·영어 버전·Live·Remix·Cover를 제외한다. YouTube oEmbed는 직접 고른 재생 링크의 존재 확인에만 사용하고 그 메타데이터를 추천 카탈로그에 등록하지 않는다.

재생 검색은 최대 50개 후보에서 곡명과 가수를 확인한다. 확인이 필요한 후보가 여러 개면 앱에서 다른 영상도 선택할 수 있다. 가수 공식 채널의 번역 제목도 설명 첫 줄의 원래 곡명과 대조한다. 음반사 등 공식 여부를 자동 확인하지 못한 채널에서 곡명과 가수가 영상 제목에 일치하면 추가 표기가 있더라도 영상 제목·채널을 보여 주고 사용자 확인을 받은 뒤 연다. 재생이 불가능해진 캐시를 제거하고 다른 재생 가능 후보를 우선하며 일시 오류는 앱에서 다시 시도할 수 있다. 확인이 필요한 후보는 자동 선택이나 캐시를 하지 않으며 구버전 앱에도 전달하지 않는다. 서버에 `YOUTUBE_API_KEY`가 있으면 사용자마다 YouTube 계정을 연결하지 않아도 검색할 수 있다. 키가 없으면 해당 사용자의 연결된 YouTube 계정이 필요하다.

## 검사

2026-10-19 최종 로컬 검수: H2 51통과/1건너뜀, 전용 PostgreSQL 52통과/0건너뜀, 최종 APK의 Android API37 43개·API24 42개 모두 통과했다. 일부 독립 H2 fixture는 PostgreSQL 설정 실행에서도 H2를 사용한다. 최종 JAR의 로컬 HTTPS·재시작·새 DB 복원15개와 구성된 비밀/사설 파일 패키지 검사를 통과했다. 정확한 빌드와 범위는 [최종 검증 기록](docs/verification.json)을 따른다. 실제 AI 연결 검사는 사용자가 완료 범위에서 제외했으며 기존 키의 공식401 invalid_api_key 근거를 보존한다. 현재 실제 추천 성공·이번 빌드의 실계정 제공자 승인·공개 출시를 통과한 것으로 기록하지 않는다.

플레이어 준비 지연·상태 표시 검사는 `node tools/check_player.cjs`로 실행한다. 실제 영상 재생과는 구분되는 스크립트 동작 검사다.

```sh
cd backend
../android/gradlew test bootJar
python3 ../tools/check_server.py build/libs/taptap-backend.jar

cd ../android
./gradlew :app:lintDebug :app:connectedDebugAndroidTest --no-configuration-cache
```

`check_server.py`는 실제 JAR을 별도 임시 폴더의 파일 H2로 실행한다. 첫 JVM에서 세션·반응·목록·순서를 저장하고 완전히 종료한 뒤 새 JVM에서 같은 내용과 인증·중복 방지를 확인한다. 검사 데이터는 종료 시 삭제하며 실제 `.env`와 AI 키를 사용하지 않는다.

`tools/check_release_secrets.py --self-test`는 합성 데이터로 검사 도구 자체를 확인한다. 최종 패키지 검사에는 APK·JAR·AAB를 함께 전달한다. 도구는 비공개 설정과 환경에서 OpenAI·Google/Spotify 비밀 및 플랫폼 토큰 암호화 키만 메모리로 읽고, 소스와 중첩 패키지에서 값의 노출·포함된 `.env`·`local.properties`·DB를 확인한다. 의도된 공개 카카오 키·클라이언트 ID는 비밀 비교 대상에서 제외한다. 결과에는 키 이름·안전하게 가린 위치만 기록하며 값이나 일치한 내용을 출력하지 않는다. 누락된 패키지·읽기 실패·크기 제한은 불완전 결과로 처리한다. 이 준비와 도구 자체 검사만으로 최종 패키지를 통과 처리하지 않는다.

로컬 서버 권한 검사는 설치된 디버그 앱과 Android 17 이상의 에뮬레이터에서 실행한다. 권한창 중 회전 후 허용하면 연결과 추천이 이어지고, 거부하면 서버 호출 없이 기기 목록과 초안으로 복구되는지 확인한다. 별도 임시 HTTP 서버를 사용하며 AI를 호출하지 않는다. 기기의 데이터·권한·화면 방향은 비공개 백업에서 복구하고 앱은 종료 상태로 남긴다. 이전 Android 버전에서는 이 검사를 건너뛴다.

```sh
python3 tools/check_local_permission.py emulator-5554
python3 tools/check_local_permission.py emulator-5554 --decision deny
```

PostgreSQL 검사는 **빈 전용 검사 DB**를 준비한 뒤 `backend/`에서 실행한다. 운영 DB 환경과 별도의 변수 이름을 사용하며, 같은 검사를 다시 실행할 때 검사 DB도 다시 비워야 한다.

```sh
TAPTAP_TEST_DATABASE_URL=jdbc:postgresql://127.0.0.1:5432/taptap_check \
TAPTAP_TEST_DATABASE_USER=taptap_check \
TAPTAP_TEST_DATABASE_PASSWORD=your-check-password \
../android/gradlew test --rerun-tasks
```

추천 조건·반응·출처 경계는 `RecommendationCheck`의 실행 가능한 assertion 검사로 확인한다. 서버 통신 검사는 사용자 소유권, 중복 저장, 재시작 보관, OpenAI JSON 계약과 호출 상한, 목록 동시 조회·삭제의 일관성을 확인한다. Android 검사는 별도 테스트 DB에서 중복 저장·반응 변경·취소·재열기 후 보관을 확인하며, 무효가 된 서버 세션으로 재연결하는 경로도 실제 HTTP 응답으로 검사한다. 테스트 DB는 종료 시 삭제한다. 기기 검사는 에뮬레이터가 필요하며 Gradle이 검사 후 대상 앱을 제거할 수 있으므로 시연 전에 디버그 APK를 다시 설치한다. 아래의 기기 실행 수와 통과 설명은 기존 기록에 해당하는 범위이며 위의 현재 체크포인트 집계와 구분한다.

`AppFlowCheckTest`는 요청 초안의 화면 재생성·탭 전환, 서버 연결 전 추천 차단과 초안 보존을 확인한다. `DynamicRecommendationCheckTest`는 전용 모의 AI 응답으로 신규 곡의 좋아요·저장·후속 요청·유지 선택의 재생성·새 AI 요청을 통한 곡 교체·재생성·검색·목록 조회·외부 검색·공유를 확인한다. 각 테스트는 기존 반응과 설정을 복구한다. `ErrorRecoveryCheckTest`는 지연 응답을 주는 로컬 서버로 진행 중인 추천의 화면 재생성·한 번만 전송·백그라운드 완료 후 첫 곡 표시를 확인한다. 좋아요·기존 목록 저장·새 목록 생성 중 재생성 후 완료 반영, 생성 후 첫 곡 저장 실패의 동일 목록 재시도, 서버 생성 성공 뒤 응답 본문이 유실되어도 같은 ID로 다시 생성 요청하여 목록 1개와 곡 저장 1회를 유지하는 흐름, 반응 쓰기 실패 후 새 화면의 오류와 기존 반응 유지도 확인하며 각 요청 횟수를 검사한다. 서버 추천 뒤 실패한 반응의 재시도가 연결 해제 후 기기 반응에 기록되지 않는지도 검사한다. 서버 카탈로그·반응 조회 후 저장 상태 조회만 실패하는 경우 기존 기기 데이터 유지, 같은 주소로 재시도, 기기 목록 복구, 저장소 변경 중 화면 재생성 시 이전 결과 제거, 초기 조회 실패 시 추천 차단과 설정 재연결도 검사한다. Android 17에서는 과거 거절 응답을 화면 재생성 중 복원하고 서버의 마지막 조회를 지연해 현재 허용된 연결·1곡 카탈로그·기기 반응 보존·서버 쓰기 0회를 확인한다. 생성·이름 변경의 서버 실패 응답 뒤 입력과 대화상자를 유지하고 오류를 표시하며, 같은 버튼으로 다시 시도해 갱신된 목록을 확인한다. Android 9 이상에서는 테스트 프로세스의 WebView 초기화를 차단해 플레이어 실패 안내와 외부 선택창도 검사한다. 기기의 WebView 제공자 설정은 변경하지 않는다. 공유 화면 검사는 실제 전송 없이 선택 화면 호출만 가로채 확인한다. `ArtworkLoaderCheckTest`는 실제 네트워크 호출 없이 늦은 사진의 재바인딩, 실패 시 기본 이미지 복원, 캐시 재사용, 종료 후 이전 요청의 적용 방지를 확인한다. 이번 추천 경로 변경에서는 Android 7과 Android 17의 추천·초안·저장·요청 복원·이미지 검사 각 6개를 실행했다. `HubFlowCheckTest`는 조회 중 OS의 플랫폼 연결 복귀·화면 재생성·초기 연결 복귀를 전용 로컬 응답으로 검사한다. 별도 서버를 지정하면 계정·변환·수정·기록 복원·공개 공유와 다른 로그인 세션이 바꾼 반응·목록의 앱 복귀 갱신도 검사한다. `HubFlowCheckTest`는 가져오기·누락 안내·수정·후보 선택·제외·전송 확인·부분 실패 재시도와 결과 복원도 전용 응답으로 검사한다. 영상 시각 수정 뒤 실제 외부 열기 주소와 음수·범위 초과 차단, 추천 중 앱 복귀의 지연 동기화 1회도 확인한다. 이전 전체 검사 실행 기록은 해당 빌드의 근거로 보존한다. 계정 통합 흐름에는 키를 사용하지 않는 전용 검사 서버 주소를 `-e fullServer http://10.0.2.2:검사포트`로 전달해야 하며, 주소가 없으면 해당 흐름만 가정 실패로 건너뛴다. 모의 연결 복귀 검사는 실제 플랫폼 OAuth 승인을 대신하지 않는다. `ConversationFlowCheckTest`는 연결 실패 때 요청 스냅샷과 유지 선택 보존, 계정이 바뀐 뒤 재시도 차단을 확인한다. 작은 화면의 현재 카드에서 스크롤해 버튼을 찾고 저장 안내가 끝난 뒤 다음 저장을 검사한다. Gradle 화면 검사는 `animationsDisabled`를 적용하며, Android Studio에서 직접 검사할 때도 [공식 Espresso 환경 안내](https://developer.android.com/training/testing/espresso/setup#set-up-environment)에 따라 검사 기기의 애니메이션을 꺼야 한다.

GitHub Actions는 초안 포함 PR과 main 브랜치의 변경에서 서버·추천 검사와 Android 디버그·릴리스 빌드·lint를 실행한다. 서버 검사는 Java 21에서 H2·[별도 PostgreSQL 서비스](https://docs.github.com/en/actions/tutorials/use-containerized-services/create-postgresql-service-containers)와 실제 JAR의 파일 DB 보관을 확인하고, Android 빌드는 프로젝트 데몬 설정에 맞춘 Java 25를 사용한다. AI 키와 실제 외부 AI 호출은 필요하지 않다. 에뮬레이터 화면 검사는 위 명령으로 별도 실행한다.

최종 산출물은 `output/release-quality/`의 `TapTap-debug.apk`, `TapTap-release-unsigned.apk`, `TapTap-release-unsigned.aab`, `taptap-backend.jar`에 고정 보관한다. 정확한 파일 해시·크기는 `output/release-quality/manifest.json`과 [검증 기록](docs/verification.json)에 있다. 릴리스 APK/AAB는 업로드 서명이 적용되지 않은 로컬 검사 파일이다. `output/apk/TapTap-debug.apk`는 편의용 복사본이며, 기존 포트8080이 사용 중인 `output/server/taptap-backend.jar`는 교체하지 않았다.
직접 빌드하면 APK는 `android/app/build/outputs/apk/debug/app-debug.apk`, 서버는 `backend/build/libs/taptap-backend.jar`에 생성된다.
