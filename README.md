# TapTap

Java Android 음악 추천·플레이리스트 앱. 2026-10-04 최신 [노션 명세](https://app.notion.com/p/3ed64b5ce98380b8b96ad80157bff1dd)와 사용자의 전체 기능 구현 지시에 맞춰 F-01~F-09, 계정·대화 조정·공개 목록·플랫폼 이전을 구현한다. 실제 서비스 연결과 공개 배포 검증 상태는 [전체 기능 기록](docs/full-feature-status.md)에 구분해 적는다.

## 실행

Android Studio에서 `android/`를 연다. `core/`, `catalog/`는 같은 상위 폴더에 두어야 한다. Android 7.0 이상에서 설치 가능하다. 첫 실행은 키 없이 사용할 수 있는 **기본 추천**이다. 40곡의 검증된 카탈로그와 공식 재생 링크로 조건을 해석하고 반응·목록을 기기의 SQLite에 보관한다. 앱 삭제 시 기기 데이터도 삭제된다.

```sh
cd android
./gradlew :app:assembleDebug :core:checkRecommendations
```

백엔드는 Java 21 이상으로 실행한다. 기본 DB는 파일 H2이며 `backend/data/`에 보관된다. 기본 바인딩은 로컬 `127.0.0.1:8080`이다.

```sh
cd backend
../android/gradlew bootJar
java -jar build/libs/taptap-backend.jar
```

서버는 `backend/`를 현재 폴더로 실행한다. `.env`와 `data/`의 상대 경로가 이 폴더를 기준으로 정해진다. 개발 중 바로 실행하려면 같은 폴더에서 `../android/gradlew bootRun`을 사용할 수 있다.

앱 설정에서 `http://10.0.2.2:8080`을 입력하면 Android 에뮬레이터가 로컬 서버에 연결된다. 서버의 곡·반응·저장 상태를 모두 확인한 뒤 연결 설정을 바꾼다. 중간 조회가 실패하면 기존 저장소와 데이터를 유지하고 주소를 고쳐 같은 창에서 다시 연결할 수 있다. 서버 연결 시 서버의 별도 반응·목록을 사용한다. 기기에 저장한 기본 추천 데이터와 자동 합치지 않는다. 연결을 해제하면 기기의 40곡 카탈로그·반응·목록을 바로 다시 사용한다. 저장소가 바뀐 상태로 화면이 재생성되면 이전 저장소의 추천 결과와 목록 위치를 복원하지 않는다. 초기 서버 데이터 조회가 실패하면 추천·반응·추천 곡 저장·교체를 비활성화하고 설정에서 재연결이나 기본 추천 복구를 제공한다.

Android 17 이상에서 로컬 서버를 연결할 때 [로컬 네트워크 권한](https://developer.android.com/privacy-and-security/local-network-permission)을 요청한다. 권한창에서 화면이 재생성돼도 연결하려던 서버 주소와 허용 결과를 이어받는다. 복원된 과거 응답보다 현재 기기의 권한 상태를 우선하여 이미 허용된 연결을 잘못 해제하지 않는다. 새 서버의 권한을 거부하면 기존 저장소를 유지하고, 사용 중인 로컬 서버의 권한을 거부하면 해당 주소를 해제한 뒤 기기의 기본 추천으로 복구한다. 서버 세션은 보관하여 다시 연결할 수 있다. 공개 HTTPS 서버 연결에는 이 권한을 요청하지 않는다.

실제 휴대폰은 HTTPS 서버 주소를 사용한다. 개발 중 LAN 테스트만 `SERVER_ADDRESS=0.0.0.0`과 개발 PC의 사설 IP를 사용한다. HTTP 테스트 연결은 디버그 앱에서만 허용된다.

서버의 `/`는 앱 소개, `/privacy`는 현재 데이터 처리 안내를 로그인 없이 제공합니다. 선택 항목 `SUPPORT_EMAIL`에 유효한 운영자 이메일을 설정하면 두 페이지에 문의 링크를 표시합니다. 실제 운영자 정보·공개 도메인·음악 서비스 승인은 별도로 확인해야 합니다. 공개 설정 절차는 [배포 안내](docs/deployment.md)를 따릅니다.

## OpenAI

서버 환경에 `OPENAI_API_KEY`를 설정하거나 `backend/.env`에 `OPENAI_API_KEY=발급받은키` 한 줄을 저장한다. 서버를 `backend/`에서 실행하면 이 파일을 자동으로 읽으며 변경 후 재시작한다. `.env`는 Git에서 제외한다. 키는 앱·저장소·로그에 넣지 않는다. 기본 모델은 `gpt-4o-mini`이며 `OPENAI_MODEL`로 바꿀 수 있다. OpenAI [Responses API](https://developers.openai.com/api/docs/guides/migrate-to-responses), [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)를 사용한다.

AI는 **사용자가 직접 작성한 500자 이하의 요청과 이전 요청 최대 8개, 검증된 태그·언어 조건 스냅샷만** 입력받아 분위기·상황·장르·언어 조건 JSON으로 변환한다. 곡명·URL을 생성하지 않는다. 서버가 등록된 곡에서 선택하며 앱 내부 좋아요를 반영하고 싫어요 곡은 제외한다. 외부 곡 데이터·외부 열기 기록·저장 행동을 AI에 보내지 않는다. `store: false`로 요청한다.

키가 없거나 연결 실패·잘못된 응답·한도 초과가 발생하면 **기본 추천**으로 이어가고 화면에서 알린다. AI 호출은 사용자당 1시간 20회, 서버 전체 UTC 하루 200회를 기본 상한으로 삼으며 시도도 횟수에 포함한다. `AI_USER_HOURLY_LIMIT`, `AI_DAILY_LIMIT`로 조정한다. 실제 과금 상한은 OpenAI 프로젝트의 예산·권한 설정도 적용한다.

2026-10-04 실제 OpenAI 호출 검사로 최초 추천·추가 요청, 영어 팝·연주곡 제외 조건, 선택 곡 유지·임시 제외를 확인했다. 결과는 허용된 카탈로그 곡만 사용하고 등록한 검사 계정은 종료 후 삭제했다. 이후 AI 구현은 바꾸지 않았으며 [실제 호출 기록](output/checks/openai-full.json)은 검사 당시 서버 파일을 명시한다. 유효한 AI 응답에서 명시 조건이 빠져도 최신 요청의 규칙 해석을 우선 적용한다. 로컬 응답 서버 검사는 실제 HTTP 요청 형식·출력 파싱·한도·기본 추천 복구를 별도로 확인한다.

## 저장·인증

서버는 앱 설치별 익명 세션을 발급한다. 32바이트 난수 토큰은 기기의 비공개 설정에, SHA-256 해시만 DB에 보관한다. 사용자 입력으로 소유자를 지정하지 않으며 모든 목록 접근을 토큰 소유자로 확인한다. 이메일·15자 이상 비밀번호로 계정을 만들면 익명 목록·반응을 같은 계정에 이어받는다. 로그인은 기기마다 별도 세션을 발급하며 같은 계정으로 다른 기기에 로그인하면 서버의 목록·반응·즐겨찾기를 함께 사용할 수 있다. 비밀번호는 무작위 salt와 PBKDF2-SHA256으로 보관한다. 로그아웃은 해당 기기 세션만 제거하고 계정 삭제는 현재 비밀번호 확인 후 계정과 소유 데이터를 삭제한다. 앱을 삭제하면 기기의 세션 연결 정보도 삭제된다.

설정·토큰·기기 DB는 클라우드 백업과 기기 간 이전에서 제외한다. Android 12 이상은 일부 기기에서 `allowBackup=false`만으로 기기 이전이 제한되지 않아 [백업 제외 규칙](https://developer.android.com/identity/data/autobackup)을 함께 적용한다.

이름 생성·변경에 실패하면 입력한 이름을 유지하고 해당 입력창과 대화상자 안에 오류를 표시한다. 오류 후 초점을 옮겨 Android 7에서 말풍선이 재시도 버튼의 터치를 가로채지 않도록 한다. 처리 중에는 이름 입력과 제출 버튼을 잠시 비활성화하고 실패하면 같은 창에서 다시 시도할 수 있다. 새 목록을 만든 뒤 곡 저장만 실패하면 생성한 목록을 유지하고 같은 목록으로 저장을 재시도한다. 서버에 목록이 만들어졌지만 응답이 끊긴 경우에도 같은 창에서 다시 시도하면 목록이 중복 생성되지 않는다. 생성 응답을 확인하기 전에 이름을 바꿨는데 이미 저장된 이름과 다르면 원래 이름으로 다시 시도하도록 안내한다. 곡 검색에서 동작을 선택하면 검색창을 닫아 저장 완료·실패 안내가 뒤에 가려지지 않게 처리한다.

같은 목록에 같은 곡을 재시도해도 한 번만 저장한다. 목록 생성·조회·상세·이름 변경·목록 삭제·곡 제거·곡 순서 변경을 지원한다. 곡 메뉴의 위로·아래로 이동으로 순서를 저장한다. 삭제 전 목록 이름과 곡 수를 확인한다. 내 목록 이름 검색과 검증된 카탈로그의 곡명·아티스트 검색을 지원한다. 검색·순서 변경·저장은 추천 반응으로 기록하지 않는다. 음원 파일은 저장하지 않는다. 영상 설명 시간표를 검토·수정·제외해 별도 외부 곡 항목으로 저장하고, 플랫폼 목록 가져오기·곡 후보 확인·명시적 전송·부분 실패 재시도를 지원한다. 외부 항목은 추천 카탈로그에 등록하지 않는다.

생성 API `POST /playlists`는 이름 `title`과 선택적인 소문자 UUID `id`를 받는다. 같은 소유자·ID·이름의 재요청은 서버 재시작 후에도 기존 목록과 현재 곡 수를 반환하며, 목록 100개 상한에서도 재시도가 가능하다. 다른 소유자의 ID는 404, 같은 ID의 다른 이름은 409, 잘못된 ID는 400으로 거절한다. ID를 생략한 기존 클라이언트도 계속 지원한다.

관리 API: `PUT /playlists/{id}`(title), `DELETE /playlists/{id}`, `PUT /playlists/{id}/items/order`(itemIds). 순서 요청은 해당 목록의 모든 항목 ID를 정확히 한 번씩 지정하며 트랜잭션으로 저장한다. `GET /playlists?q=...`, `GET /catalogue?q=...`는 100자 이하 검색어를 받는다. 검색은 대소문자·유니코드 호환 문자 차이를 정규화하고 모든 검색 단어를 확인한다.

목록에 추가할 때 곡 정보와 출처를 함께 보관하여 카탈로그가 변경되어도 저장한 곡 정보를 유지한다. 목록 상세와 스크롤 위치는 화면 재생성 후 복원한다. 진행 중인 반응·목록 작업도 완료까지 유지하고 새 화면에서 최신 상태와 오류를 확인한다. 새 목록 생성과 첫 곡 저장은 화면 재생성과 관계없이 이어 실행한다. 화면 종료 시 열려 있는 대화상자를 닫아 이전 창이 새 화면의 입력을 가로채지 않도록 한다. 서버의 목록 제목·곡은 한 번에 조회하여 동시 삭제 중 빈 목록으로 잘못 표시하지 않는다. 삭제 후 응답이 끊겨 다시 시도한 경우 이미 삭제된 목록은 목록 화면으로 복구한다. 연결 모드를 바꾼 뒤 이전 실패의 재시도로 다른 저장소에 쓰지 않는다.

상세의 ‘목록 텍스트 공유’는 순서대로 곡명·아티스트·검증된 YouTube Music 링크(없으면 출처 링크)를 Android 공유 화면에 전달한다. 사용자가 공유 대상을 고른다. ‘공개 설정 · 공유 링크’에서 목록을 직접 공개하면 읽기 전용 웹 링크를 공유할 수 있다. 비공개로 바꾸면 기존 링크가 즉시 닫힌다. ‘발견’에서 공개 목록 검색·즐겨찾기·복사·앱 즐겨찾기 수에 따른 순위를 제공한다.

추천 결과의 ‘추천 N곡 모두 저장’으로 현재 추천을 기존 목록 또는 새 목록에 한 번에 담을 수 있다. `POST /playlists/{id}/items/batch`는 `trackIds`로 서로 다른 1~10곡을 받는다. 기기와 서버 모두 일괄 저장을 트랜잭션으로 처리하므로 일부 곡만 저장되는 실패를 방지한다. 같은 추천을 다시 저장해도 목록의 곡이 중복되지 않는다.

PostgreSQL을 사용할 때 `DATABASE_URL`을 JDBC URL로, `DATABASE_USER`, `DATABASE_PASSWORD`를 환경에 설정한다. 동일한 SQL 스키마를 사용한다. H2와 실제 PostgreSQL 15에서 저장·소유권·중복 방지·목록 순서·동시 조회/삭제·서버 재시작을 확인했다. 단일 서버 프로토타입으로 쓰기를 직렬 처리하며 여러 서버로 확장할 때 DB upsert·호출 한도 동시성 검토가 필요하다. 호출 한도는 기존 ISO 시간 기록을 `Instant`로 비교하여 UTC 자정 직후와 서로 다른 소수점 정밀도에서도 정확히 계산한다.

## 추천 화면·수정

프로젝트 세션의 `output/pdf/TapTap_모바일_UIUX_레퍼런스.pdf` 2~3쪽 시안과 사용자가 첨부한 Swipefy 화면을 참고한다. 작은 중앙 제목 아래 큰 실제 영상 썸네일을 배치하고, 사진에서 얻은 색을 따뜻한 배경에 반영한다. 곡명·아티스트·추천 이유는 모서리가 8dp로 둥근 차콜색 겹침 카드에 표시한다. 하단에는 선택 탭을 형광색으로 강조하는 ‘추천’·‘변환’·‘발견’·‘내 목록’·‘계정’ 다섯 탭을 제공한다. 좌우 스와이프와 하단에 고정한 검정 원형의 이전·싫어요·재생·좋아요·다음 버튼으로 탐색한다. 싫어요는 코럴, 좋아요는 초록, 재생은 흰색으로 구분한다.

카드의 곡 수정 아이콘·‘다른 앱’·‘목록에 저장’과 요청 수정·모두 저장을 제공한다. 버튼의 실제 터치 영역은 48dp 이상이며 줄바꿈과 Android 기본 세로 스크롤을 적용한다. 좁은 화면이나 큰 글씨에서는 카드와 카드 바깥의 추천 화면을 스크롤해 곡 정보·요청 수정·전체 저장에 접근한다. 반응·탐색 바는 추천 스크롤 바깥에 고정한다. 되돌리기·재시도·저장 안내는 보이는 반응 바 또는 하단 메뉴 위에 표시해 시스템 버튼에 가려지지 않게 처리한다. 목록·대화상자의 낮밤 색은 유지한다. 변환·플랫폼 연결·공개 목록은 각 탭에서 실제 기능 화면으로 이어진다.

앱 글꼴은 [Pretendard 1.3.9](https://github.com/orioncactus/pretendard/releases/tag/v1.3.9)를 사용한다. 본문은 Regular, 제목·버튼은 SemiBold, 목록 제목은 Bold로 구분한다. 정적 폰트와 SIL Open Font License 원문을 앱에 포함하므로 인터넷 없이도 같은 글꼴을 표시한다. Android 7에서도 AppCompat 경로로 입력창과 대화상자에 적용한다.

결과에 실제 해석된 조건을 표시한다. ‘요청 수정’으로 직접 요청을 고친 뒤 다시 추천받을 수 있다. 카드의 ‘곡 수정’에서 같은 조건의 다른 곡으로 바꾸거나 이번 결과에서만 제외하고 되돌릴 수 있다. 현재/이미 제외한 곡은 교체 후보에서 빼고 기존 좋아요·싫어요를 유지한다. 교체는 검증된 카탈로그 안에서 처리하며 추가 AI 호출은 하지 않는다. 임시 제외는 영구적인 싫어요로 저장하지 않는다. 조건·수정 결과와 아직 제출하지 않은 요청 초안은 화면 재생성 후 복원한다. 화면을 다시 만들 때 진행 중인 추천을 유지하여 같은 AI 요청을 다시 보내지 않으며, 새 추천은 첫 곡부터 표시한다. ‘이어서 요청 · 곡 유지’는 이전 조건을 유지하며 최신 요청으로 분위기·장르·언어를 바꾸고 직접 선택한 곡을 남긴다. 이전 요청 표시가 8개를 넘어도 검증된 조건 스냅샷으로 조건을 유지한다. 운영체제가 앱 프로세스를 종료한 경우 같은 요청·유지/제외 곡을 보관하고 직접 재시도하며 자동 재전송하지 않는다. 재시도는 서버와 계정 소유자가 같은 경우에만 허용한다. 화면을 바꾸면 입력 키보드를 닫고, 순번과 플레이어 상태 변경을 화면 읽기에 전달한다.

## 영상 변환·플랫폼 연결

‘변환’에서 YouTube 원본 URL과 설명의 시간표를 입력한다. `YOUTUBE_API_KEY` 또는 연결된 YouTube 계정이 있으면 공식 API로 영상 제목·설명·길이를 조회할 수 있다. 시간표는 최대 100행·영상 최대 6시간을 지원하며, 잘못된 시간·중복·누락된 곡 정보는 검토 대상으로 남긴다. 사용자가 곡명·아티스트·시작 시간을 고치거나 행을 제외한 뒤 저장한다. 원본 영상의 해당 위치를 공식 플레이어 또는 브라우저로 열며 음원 추출이나 곡 추측은 하지 않는다.

Spotify·YouTube Music·Apple Music 연결은 각각 개발자 앱 설정이 필요하다. [서버 환경 템플릿](backend/.env.example)의 항목을 비공개 `backend/.env`에 설정한다. 암호화 키 `PLATFORM_TOKEN_SECRET`은 32바이트 난수의 Base64 값이며 저장된 연결을 읽을 때 필요하므로 유지한다. Spotify/Google은 한 번만 사용하는 state·PKCE·세션 결속을 적용하고, Apple은 서버의 MusicKit 인증 페이지에서 사용자 허용을 받는다. 플랫폼 토큰은 AES-GCM으로 암호화하며 앱이나 공개 응답에 전달하지 않는다. 설정이 없는 플랫폼은 계정 화면에서 사용 불가를 표시한다.

공식 API로 읽은 원본 목록을 앱에 별도 항목으로 저장한다. 같은 원본의 반복 곡은 서로 다른 행으로 보존하고, 재시도는 같은 작업 ID를 사용한다. 대상 플랫폼의 ID·ISRC·곡명·아티스트·버전·길이를 비교해 후보를 제시하고, 사용자가 각 곡의 후보 또는 제외를 확인해야 새 비공개 플랫폼 목록을 만든다. 전송 결과는 성공·실패·확인 필요·대기를 표시한다. 응답이 끊긴 경우 원격 목록 순서와 작업 표식을 대조하여 중복 추가를 피하고, 남은 곡만 같은 작업으로 이어 보낸다. 작업 기록에서 기존 변환·전송을 다시 열거나 기록만 삭제할 수 있다. 앱 목록을 삭제한 뒤에도 변환 기록에서 같은 원본 목록을 다시 저장할 수 있으며 다른 계정의 목록 ID는 사용할 수 없다. 가져온 목록의 제목·곡·검토 기록은 함께 저장하고 실패하면 함께 복원한다.

외부 목록 변경은 ‘목록 변경 미리보기’로 추가·제거·변경을 확인한 뒤 반영한다. 같은 앱 목록에 별도로 저장한 추천곡과 다른 가져오기 원본은 보존한다. 외부 상세 정보는 원본 조회 후 30일 뒤 삭제하고, 제목·곡 수동 수정이나 재저장으로 그 기간을 연장하지 않는다. 최소 원본 참조만 남겨 다시 조회할 수 있도록 하며 공개 스냅샷에서도 만료 정보를 제거한다. 플랫폼 연결 해제는 해당 계정의 플랫폼 토큰·작업·외부 항목과 다른 원본 기록에 남은 해당 플랫폼 후보·선택 정보도 제거한다. 플랫폼 데이터·영상 설명·이미지·연결 기록을 추천 AI나 개인화에 보내지 않는다.

공식 API 계약 검사는 로컬 응답 서버로 재현한다. 실제 Spotify 개발 모드·Google OAuth/할당량·Apple MusicKit 계정 연결은 개발자 설정과 실계정이 있어야 검증할 수 있다. 공개 HTTPS 실행은 [배포 안내](docs/deployment.md)를 따른다.

## 곡 데이터·재생

`catalog/tracks.json`: MusicBrainz 공식 API에서 조회한 실제 녹음 ID·곡명·아티스트·원본 링크. [핵심 메타데이터 CC0](https://musicbrainz.org/doc/About/Data_License)만 사용하고 분위기·상황 태그는 TapTap 샘플로 직접 작성했다. MusicBrainz에서 사용자 태그·평점·앨범 표지·가사·음원은 가져오지 않는다. 샘플 태그는 추천 품질 평가가 완료된 객관적 속성으로 간주하지 않는다.

곡 사진은 검증된 YouTube 영상의 실제 썸네일을 표시용으로 불러온다. `maxresdefault`를 우선 조회하고 실패하면 `hqdefault`로 다시 시도하며, 두 시도는 15초의 공통 마감 기준을 사용한다. 8MiB 메모리 캐시로 재사용하고 응답당 2MiB·디코딩 100만 픽셀 상한을 적용한다. 사진과 사진에서 얻은 배경색은 AI 입력이나 추천 근거로 사용하지 않으며 추가 AI 호출도 없다. 실패하면 기본 이미지를 표시하고 추천과 저장은 계속 사용할 수 있다. 카드가 바뀐 뒤 도착한 이전 사진은 적용하지 않는다.

검증한 재생 링크가 있는 곡은 [공식 YouTube IFrame 플레이어](https://developers.google.com/youtube/iframe_api_reference)를 표시한다. 사용자가 플레이어의 재생을 눌러야 시작한다. 화면 이동·외부 앱 이동·백그라운드 진입 시 플레이어를 종료한다. 앱 ID를 `loadDataWithBaseURL` 출처로 사용해 [공식 클라이언트 식별 요구](https://developers.google.com/youtube/terms/required-minimum-functionality)를 적용한다. 곡의 공식 영상 링크가 없으면 검색으로 연결한다. ‘다른 앱’ 선택창에서 플랫폼 아이콘과 연결 방식을 표시한다. Spotify는 곡명·아티스트 검색, YouTube Music은 검증된 영상 직접 연결을 제공하며 영상 링크가 없으면 검색으로 연결한다. WebView 초기화 실패나 지역·임베드 제한에 따른 재생 실패는 안내와 외부 열기로 복구한다.

카탈로그 재검증: `python3 tools/verify_catalog.py`. 이 작업은 명시적으로 실행할 때만 네트워크를 사용하며 MusicBrainz 요청 간격을 1초 이상 둔다. 동명 코멘터리·영어 버전·Live·Remix·Cover를 제외한다. YouTube oEmbed는 직접 고른 재생 링크의 존재 확인에만 사용하고 그 메타데이터를 추천 카탈로그에 등록하지 않는다.

## 검사

플레이어 준비 지연·상태 표시 검사는 `node tools/check_player.cjs`로 실행한다. 실제 영상 재생과는 구분되는 스크립트 동작 검사다.

```sh
cd backend
../android/gradlew test bootJar
python3 ../tools/check_server.py build/libs/taptap-backend.jar

cd ../android
./gradlew :app:lintDebug :app:connectedDebugAndroidTest --no-configuration-cache
```

`check_server.py`는 실제 JAR을 별도 임시 폴더의 파일 H2로 실행한다. 첫 JVM에서 세션·반응·목록·순서를 저장하고 완전히 종료한 뒤 새 JVM에서 같은 내용과 인증·중복 방지를 확인한다. 검사 데이터는 종료 시 삭제하며 실제 `.env`와 AI 키를 사용하지 않는다.

로컬 서버 권한 검사는 설치된 디버그 앱과 Android 17 이상의 에뮬레이터에서 실행한다. 권한창 중 회전 후 허용하면 연결과 추천이 이어지고, 거부하면 서버 호출 없이 기본 추천으로 복구되는지 확인한다. 별도 임시 HTTP 서버를 사용하며 AI를 호출하지 않는다. 기기의 데이터·권한·화면 방향은 비공개 백업에서 복구하고 앱은 종료 상태로 남긴다. 이전 Android 버전에서는 이 검사를 건너뛴다.

```sh
python3 tools/check_local_permission.py emulator-5554
python3 tools/check_local_permission.py emulator-5554 --decision deny
```

PostgreSQL 검사는 **빈 전용 검사 DB**를 준비한 뒤 `backend/`에서 실행한다. 운영 DB 환경과 별도의 변수 이름을 사용하며, 같은 검사를 다시 실행할 때 검사 DB도 다시 비워야 한다.

```sh
TAPTAP_TEST_DATABASE_URL=jdbc:postgresql://127.0.0.1:5432/taptap_check \
TAPTAP_TEST_DATABASE_USER=taptap_check \
TAPTAP_TEST_DATABASE_PASSWORD=your-check-password \
../android/gradlew test --rerun-tasks
```

추천 조건·반응·출처 경계는 `RecommendationCheck`의 실행 가능한 assertion 검사로 확인한다. 서버 통신 검사는 사용자 소유권, 중복 저장, 재시작 보관, OpenAI JSON 계약과 호출 상한, 목록 동시 조회·삭제의 일관성을 확인한다. Android 검사는 별도 테스트 DB에서 중복 저장·반응 변경·취소·재열기 후 보관을 확인하며, 무효가 된 서버 세션으로 재연결하는 경로도 실제 HTTP 응답으로 검사한다. 테스트 DB는 종료 시 삭제한다. 기기 검사는 에뮬레이터가 필요하며 Gradle이 검사 후 대상 앱을 제거할 수 있으므로 시연 전에 디버그 APK를 다시 설치한다.

`AppFlowCheckTest`는 제출 전 요청 초안의 화면 재생성·탭 전환·이전 결과 복귀를 확인하고, 추천·스와이프/버튼 탐색·반응 상태·새 목록 저장·중복 저장·추천 전체 저장·추천 곡 교체·임시 제외·되돌리기·조건 복원·목록 상세 복원·공유 화면 호출·화면 재생성·앱 재열기·출처 확인·곡 제거·이름 변경·순서 변경·목록 삭제·목록/곡 검색·검색에서 저장한 뒤 완료 안내와 저장 목록 재열기를 화면에서 이어 검사한다. 기존 반응과 설정은 검사 후 복구하고 검사에서 만든 목록만 제거한다. `ErrorRecoveryCheckTest`는 지연 응답을 주는 로컬 서버로 진행 중인 추천의 화면 재생성·한 번만 전송·백그라운드 완료 후 첫 곡 표시를 확인한다. 좋아요·기존 목록 저장·새 목록 생성 중 재생성 후 완료 반영, 생성 후 첫 곡 저장 실패의 동일 목록 재시도, 서버 생성 성공 뒤 응답 본문이 유실되어도 같은 ID로 다시 생성 요청하여 목록 1개와 곡 저장 1회를 유지하는 흐름, 반응 쓰기 실패 후 새 화면의 오류와 기존 반응 유지도 확인하며 각 요청 횟수를 검사한다. 실제 서버 추천 뒤 실패한 반응의 재시도가 기본 추천 모드의 기기 반응에 기록되지 않는지도 검사한다. 서버 카탈로그·반응 조회 후 저장 상태 조회만 실패하는 경우 기존 기기 데이터 유지, 같은 주소로 재시도, 기본 모드의 40곡 복구, 저장소 변경 중 화면 재생성 시 이전 결과 제거, 초기 조회 실패 시 추천 차단과 설정 재연결도 검사한다. Android 17에서는 과거 거절 응답을 화면 재생성 중 복원하고 서버의 마지막 조회를 지연해 현재 허용된 연결·1곡 카탈로그·기기 반응 보존·서버 쓰기 0회를 확인한다. 생성·이름 변경의 서버 실패 응답 뒤 입력과 대화상자를 유지하고 오류를 표시하며, 같은 버튼으로 다시 시도해 갱신된 목록을 확인한다. Android 9 이상에서는 테스트 프로세스의 WebView 초기화를 차단해 플레이어 실패 안내와 외부 선택창도 검사한다. 기기의 WebView 제공자 설정은 변경하지 않는다. 공유 화면 검사는 실제 전송 없이 선택 화면 호출만 가로채 확인한다. `ArtworkLoaderCheckTest`는 실제 네트워크 호출 없이 늦은 사진의 재바인딩, 실패 시 기본 이미지 복원, 캐시 재사용, 종료 후 이전 요청의 적용 방지를 확인한다. 화면 검사는 Android 7(API 24)에서 해당하지 않는 WebView 차단·로컬 네트워크 권한 검사 두 개를 제외한 기존·대화 검사 13개, Android 17(API 37)에서 15개로 구성한다. `HubFlowCheckTest`는 조회 중 OS의 플랫폼 연결 복귀·화면 재생성·초기 연결 복귀를 전용 로컬 응답으로 검사한다. 별도 서버를 지정하면 계정·변환·수정·기록 복원·공개 공유와 다른 로그인 세션이 바꾼 반응·목록의 앱 복귀 갱신도 검사한다. `HubFlowCheckTest`는 가져오기·누락 안내·수정·후보 선택·제외·전송 확인·부분 실패 재시도와 결과 복원도 전용 응답으로 검사한다. 영상 시각 수정 뒤 실제 외부 열기 주소와 음수·범위 초과 차단, 추천 중 앱 복귀의 지연 동기화 1회도 확인한다. 각 기기 Hub 3개를 포함해 합계 34개다. 계정 통합 흐름에는 키를 사용하지 않는 전용 검사 서버 주소를 `-e fullServer http://10.0.2.2:검사포트`로 전달해야 하며, 주소가 없으면 해당 흐름만 가정 실패로 건너뛴다. 모의 연결 복귀 검사는 실제 플랫폼 OAuth 승인을 대신하지 않는다. `ConversationFlowCheckTest`는 추가 요청의 조건·유지 곡·입력 초안 회전 복원·세션 변경 재시도를 확인한다. 작은 화면의 현재 카드에서 스크롤해 버튼을 찾고 저장 안내가 끝난 뒤 다음 저장을 검사한다. Gradle 화면 검사는 `animationsDisabled`를 적용하며, Android Studio에서 직접 검사할 때도 [공식 Espresso 환경 안내](https://developer.android.com/training/testing/espresso/setup#set-up-environment)에 따라 검사 기기의 애니메이션을 꺼야 한다.

GitHub Actions는 초안 포함 PR과 main 브랜치의 변경에서 서버·추천 검사와 Android 디버그·릴리스 빌드·lint를 실행한다. 서버 검사는 Java 21에서 H2·[별도 PostgreSQL 서비스](https://docs.github.com/en/actions/tutorials/use-containerized-services/create-postgresql-service-containers)와 실제 JAR의 파일 DB 보관을 확인하고, Android 빌드는 프로젝트 데몬 설정에 맞춘 Java 25를 사용한다. AI 키와 실제 외부 AI 호출은 필요하지 않다. 에뮬레이터 화면 검사는 위 명령으로 별도 실행한다.

공유 가능한 APK: `android/app/build/outputs/apk/debug/app-debug.apk`.
실행 가능한 서버: `backend/build/libs/taptap-backend.jar`.
